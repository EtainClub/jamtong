# 잼통 정원 개편 — 내 방 · 1촌 · 상점 · 거대 잡초 2.0

> 상태: 설계안 (2026-11-14). 0–3단계(틀·방·1촌·거대 잡초 2.0)를 구현했다 — 각 절의 "구현하며 바꾼 것"을 본다. 바탕 문서는 `docs/garden-game.md`(이하 "본문서")이고,
> 그 §1의 선은 이 안에서도 그대로 지킨다. 수치는 모두 첫 실험값이다.

## 0. 한 줄 요약

> 정원의 첫 화면을 **내 방**으로 바꾼다. 거둔 품종을 방에 전시하고, 1촌을 맺어 서로의 방에
> 마실을 다닌다. 상점은 방 꾸미기까지 다루는 카테고리 상점이 되고, 거대 잡초는 "몫 60방 쓰기"에서
> "같은 때 모여 빈틈을 치고, 몫을 다 쓴 뒤에도 돕는" 놀이로 바뀐다.

방은 게임 안의 **근거 전시장**이기도 하다. 방에 걸린 쪽지 액자를 누르면 그 claim과 출처,
원본 페이지가 열린다. 방 링크를 받은 지인이 꾸민 방을 구경하다 근거에 닿는다.

| 탭 | 7개가 한 줄 (텃밭·상점·꽃밭·광장·온실·도감·이웃) | 360px에서 탭 하나가 45px 남짓. 첫 화면이 "지금 할 일"을 말해 주지 않는다 |
| 잼 쓸 곳 | 씨앗·비료·필살기·텃밭 12칸(1,200잼)에서 끝 | 대표 열매 하나가 380–520잼이다. 오래 한 사람은 잼이 쌓이기만 한다 |
| 친구 | `friends` = 내가 가 본 공개 정원 30곳, 이 기기 장부 | 한쪽만 아는 관계다. 상대는 내가 왔는지 물 알림으로만 안다 |

정리하면 고칠 곳은 넷이다. **들어오자마자 할 일이 없다 / 잼과 열매가 갈 곳이 없다 /
사람 사이가 한쪽 방향이다 / 거대 잡초가 머릿수 세기다.** 아래 설계가 하나씩 맡는다.

## 2. 빌리는 것과 빌리지 않는 것

싸이월드에서 구조를 빌린다. 이름·그림·음악은 잼통 것으로 만든다(본문서 §1).

| 싸이월드 | 잼통 정원 | 다르게 하는 점 |
|---|---|---|
| 미니홈피 첫 화면 | **정원 홈** — 새 소식, 내 방, 1촌평, 방명록 | "지금 할 일"이 소식 칸에 뜬다 |
| 미니룸 | **내 방** | 인테리어의 절반은 사서가 아니라 **거둬서** 얻는다 |
| 도토리 | 잼 (이미 있음) | 현금으로 사지 못한다 |
| 일촌 신청·수락·끊기 | **1촌** | 같다. 끊어도 상대에게 알리지 않는다 |
| 일촌명 | 1촌 이름표 | 정해 둔 이름표에서 고른다(글을 짓지 않는다) |
| 일촌평·방명록 | 1촌평·방명록 | 1차는 정해 둔 문구와 스티커만 |
| 파도타기 | **마실** | 1촌 목록은 기본 비공개. 방명록과 "아무 방이나"로 건너간다 |
| TODAY / TOTAL | 오늘 손님 / 모든 손님 | 내 방에만 보인다. 순위표는 없다 |
| 선물하기 | **하지 않는다** | 사용자 간 아이템 이동은 없다(§1). 주고받는 것은 물·문구·스티커뿐 |
| 미니미 | 뒤로 미룬다(§9) | 그림 비용이 크다 |
| 기간제 아이템 | 하지 않는다 | 산 것은 사라지지 않는다 |

본문서 §1과 부딪히는 자리와 고른 길:

| 선 | 방·1촌에서 생기는 위험 | 고른 길 |
|---|---|---|
| 사용자 간 거래 없음 | 가구 선물, 씨앗 선물 | 없다. 1촌의 이득은 물 주기와 함께 싸우기뿐 |
| 닉네임만, 청소년 보호 | 방명록·1촌평의 자유 글, 모르는 사람의 신청 | 문구는 고르는 것만. 신청 받기를 끌 수 있고, 차단이 있다. 쪽지(DM)는 없다 |
| 공개 랭킹 없음 | 손님 수 순위, 방 점수 | 손님 수는 그 방에서만 보인다. 방 점수는 만들지 않는다 |
| 정치 성향 추론 집계 없음 | 1촌 관계망은 지지자 관계망이다 | 1촌 목록은 본인만 본다. 계측에는 수만 보낸다(누구와 맺었는지 보내지 않는다) |
| 사람이 지은 글은 우리 카드에 싣지 않는다 | 방 자랑 카드 | 카드에는 품종표의 이름·그림·숫자만 |
| 반론을 치울 것으로 그리지 않는다 | 액자에 사실만 걸게 될 수 있다 | 반론·한계 쪽지도 같은 액자로 걸린다. 종류 표시는 떼지 못한다 |

### 3.1 탭 7 → 5, 아래로

| 새 탭 | 담는 것 | 옛 탭 |
|---|---|---|
| 🏠 방 | 정원 홈(새 소식·내 방·1촌평·방명록), 방 꾸미기, 도감(방의 책장) | 도감 |

| ⛲ 광장 | 광장 · 꽃밭 (위쪽 두 칸 전환), 거대 잡초 | 광장, 꽃밭 |

  위쪽 바에 "← 잼통"을 둔다. 하단 바를 둘 겹치지 않는다.
  정보 페이지로 돌아가는 길이 한 번 더 멀어지므로, 쪽지·액자·전광판의 원본 링크는 지금처럼 늘 연다.
  (대안: 사이트 탭을 그대로 두고 정원 탭 5개를 위쪽에 붙인다. 구현은 쉽지만 손이 멀다.)
- 잼 지갑은 모든 탭의 위쪽 바에 고정한다. 날씨 배지는 그 옆.
- 자세히 보기·사기·놓기는 모두 **아래쪽 시트**로 띄운다(v1.17의 작물 자세히 보기와 같은 틀).
- 주소는 `?tab=room|beds|plaza|shop|friends`. 옛 값(`flowers`, `greenhouse`, `dex`, `neighbors`)은
  새 탭의 해당 칸으로 받는다 — "같이 잡자" 링크가 깨지지 않게.
- 코치의 탭 팁(`TipTab`)도 새 탭에 맞춘다.

## 4. 내 방

### 4.1 방의 모양

- **정면에서 본 방**이다. 뒷벽 한 장과 바닥. 비스듬한 입체(아이소메트릭)로 하지 않는다 —
  손가락으로 놓기 어렵고, 그림을 방향마다 그려야 한다. 그림은 지금 정원처럼 SVG로 그린다.
- **칸에 놓는다.** 벽 6칸 한 줄, 바닥 6칸 두 줄(뒷줄·앞줄)에서 시작한다. 가구는 1칸 또는 2칸.
- 벽지와 바닥재는 통째로 바뀐다. 창문은 벽 2칸이고, 창밖은 지금 날씨(단비·별똥별)를 그린다.
- 방 넓히기(상점 → 확장): 6칸 → 8칸 → 10칸. 텃밭 넓히기 다음의 큰 잼 목표다.

| 단계 | 벽 / 바닥 | 값 |
|---|---|---|
| 작은 방 | 6 / 12 | 처음부터 |
| 넓은 방 | 8 / 16 | 잼 1,500 |
| 볕 드는 방 | 10 / 20 | 잼 5,000 |

### 4.2 방에 놓는 것 — 거둔 것과 산 것

**거둔 것(전시품).** 상점에서 팔지 않는다. 이 사람이 무엇을 길렀는지가 방에 남는다.

| 전시품 | 얻는 길 | 놓는 곳 | 누르면 |
|---|---|---|---|
| 🪴 화분 | 바구니의 열매 하나를 "전시하기" (잼으로 졸이는 대신) | 바닥·선반 | 품종 이름, 원본 페이지 링크 |
| 🌳 나무 | 다년생 열매를 전시 | 바닥(키 큼) | 같다 |
| ✨ 변이 화분 | 변이가 붙은 열매를 전시 — 황금 화분, 무지개 화분… | 바닥 | 변이 이름과 공개 확률 |
| 🖼 쪽지 액자 | 쪽지 도감의 쪽지를 "액자에 걸기" (액자틀은 상점, 잼 30) | 벽 | **쪽지 전문, 종류 표시, 출처, 원본 링크** |
| 🏵 만개 명패 | 내가 정원지기인 만개 업적 | 벽 | 업적 꽃밭 |
| 🏅 칭호 장식 | 칭호 ★마다 | 선반 | 칭호 설명 |
| 🌵 악초 박제 | 거대 잡초 전리품(§7.4) | 바닥·벽 | 그 악초의 성질 |

- **열매는 졸이거나 전시하거나 둘 중 하나다.** 황금 열매(×10)를 잼으로 바꿀지 방에 둘지가 고민이 된다.
  도감의 품종 × 변이 칸이 방에서 보이는 물건이 된다.
- 화분의 그림은 품종표의 그림(`PlantArt`, 품종 `seed`로 정해짐)을 그대로 쓴다. 품종 220여 개의 그림을
  따로 그리지 않는다. 등급은 화분 크기, 변이는 화분 빛깔로 나타낸다.
- **쪽지 액자는 글을 저장하지 않는다.** 공개 문서에는 쪽지 id만 싣고, 글은 보는 화면이 품종표에서
  읽는다. 사람이 지은 글이 액자에 들어갈 길이 없다. 콘텐츠가 고쳐지면 액자도 따라 바뀌고,
  쪽지가 콘텐츠에서 빠지면 액자는 빈 틀이 된다.
- 산 빈 액자틀은 꾸미기 ‘가구’에 보이며, 빈 상태로도 벽에 걸 수 있다. 도감에서 쪽지를 걸 때는
  보관함의 빈 틀부터 쓰고, 남은 틀이 모두 벽에 걸려 있으면 그 자리에서 쪽지를 채운다.
- 액자는 쪽지의 종류 표시를 그대로 단다 — 주장이면 누구의 주장인지, 미검증이면 그 표시까지.
  반론·한계 쪽지도 같은 틀에 걸린다. 사실 쪽지만 금테를 두르는 식의 차별을 두지 않는다.
- 전시한 것은 치워도 사라지지 않고 보관함으로 간다. 열매로 되돌릴 수는 없다.

**산 것(가구).** 잼으로 산다. 효과는 없다 — 꾸밈일 뿐이다. 성장 버프를 가구에 달면 방이 스펙이 된다.

| 갈래 | 예 | 값(잼) |
|---|---|---|
| 벽지·바닥재 | 연두 줄무늬, 나무 마루, 잔디 | 150–600 |
| 창문 | 둥근 창, 넓은 창 | 300–800 |
| 가구 | 침대, 책장, 소파, 책상 | 200–1,500 |
| 소품·조명 | 스탠드, 러그, 물뿌리개, 라디오 | 50–400 |
| 한정 | 주마다 바뀌는 진열, 계절 축제 | 400–2,000 |
| 전리품 가구 | 뿌리 조각으로만(§7.4) | 조각 5–30 |

몇 가지 가구는 **바로가기**다. 책장을 누르면 도감, 우편함은 방명록, 라디오는 배경음악 고르기.
효과가 아니라 길이다.

### 4.3 꾸미기 (손가락 기준)

1. `✏️ 꾸미기` → 방이 위에 붙고 아래 시트에 보관함이 뜬다(전시품·가구·벽·바닥 칩).
2. 물건을 누르면 놓을 수 있는 칸이 빛난다. 칸을 누르면 놓인다. **끌지 않는다.**
3. 놓인 물건을 누르면 `옮기기 · 넣기`.
4. `완료`에서 저장. 꾸미는 동안은 공개 문서를 고치지 않는다.

### 4.4 자료

```ts
// GardenData에 더한다 (store.ts)
room: {
  size: 0 | 1 | 2;
  wall: string;                 // 벽지 id
  floor: string;                // 바닥재 id
  mood: string;                 // 오늘의 기분 id
  placed: Array<{ at: string; it: string }>;   // at = "w3" | "b2" | "f5", it = 물건 id
  owned: Record<string, number>;               // 산 가구
  shown: Array<{ id: string; kind: "pot" | "tree" | "frame" | "trophy";
                 species?: string; mut?: Mutation[]; note?: string }>;  // 전시품
}
```

- 가구표는 `room/catalog.ts`에 코드로 둔다(id·크기·놓는 곳·값·그림). 품종표처럼 화면은 표에 있는 id만 그린다.
- 공개 문서 `gardens/{gid}`에 `room`(벽·바닥·기분·placed의 압축형)을 더한다. 규칙은 키와 길이
  (placed 40개까지, 문자열 길이)만 본다. 안의 값은 지금 텃밭 목록과 같이 화면이 표로 거른다.
- 방은 개인 정원 장부다. 손으로 고쳐 가구를 얻는 반칙은 혼자의 문제로 둔다(본문서 §3.12).
- `rules.ts`(1,112줄)·`store.ts`(865줄)에 더 얹지 않는다. `features/garden/room/`에 표·규칙·화면을 따로 둔다.

### 4.5 내 키보드 (2026-11-14)

방에 놓는 가구 `⌨️ 내 키보드`(바닥 2칸, 잼 400, 바로가기 `keyboard`). 누르면(내 방이든 남의 방이든) 아래 시트에 큰 키 넷이 뜨고,
누르면 소리가 난다. 시트가 열려 있으면 1–4 · A S D F로도 누른다. 방 음악 다섯 곡은 그대로 두고 그 위에 더한 놀이다.

**정한 것(사용자 결정)**

| 것 | 결정 |
|---|---|
| 방 음악 | 다섯 곡 그대로. 키보드는 덧붙임 |
| 녹음 | 한다. 기본은 바꾼 목소리(🤖 로봇). **원래 목소리는 따로 고르고 확인해야** 올라간다("원래 목소리가 그대로 올라가고, 방을 공개하면 누구나 들을 수 있어요") |
| 듣는 사람 | 공개 방을 볼 수 있는 **모두**(1촌만이 아니다) |

**키 하나 = 그림 + 소리.**

- 그림: 12×12 도트, 8색 팔레트(0 = 투명). 144자 문자열(`'0'`–`'7'`). 그림판은 누르고 끌어 칠하기, 지우개, 모두 지우기,
  획마다 여러 단계 되돌리기(모두 지우기도 포함), 거울. 편집을 열었을 때의 그림까지 되돌릴 수 있다. 판 위에서는 화면이 밀리지 않는다(`touch-action: none`). 방 그림의 키보드에도 작게 그린다.
- 소리: 정해 둔 스물(오르골 도·미·솔·높은 도, 풍경, 물방울, 두꺼비, 수탉, 새소리, 북, 실로폰, 잼 뚜껑 퐁, 잡초 뽑기 쑥,
  자전거 따릉, 야옹, 손뼉, 용수철 띠용, 반짝, 보글보글, 휘파람) · 소리 없음 · 내 녹음. 정해 둔 소리는 모두 Web Audio로
  그 자리에서 만든다(`room/keyboardSound.ts`) — 소리 파일이 없다.
- 박자: 방 음악이 흐르면 키 소리를 그 곡의 다음 8분음표에 맞춘다(`feedback.ts`의 `musicGrid`, `keyboard.ts`의 `snapTime`). 아니면 바로.
- 소리 켜기: 소리를 꺼 두었어도 **키를 누르면 소리가 난다**(누름이 곧 사용자 터치다 — `keyAudio()`가 그 안에서 오디오를 연다).
  배경음악은 켜지 않는다. 무음 스위치는 그대로 따른다(ambient 세션).

**자료.**

```ts
room.keys: Array<{ face: string /* 144자 */; sound: string /* 소리 id | "rec" | "none" */; ver: number /* 마지막 녹음 판, 0=없음 */ }>  // 꼭 넷
// 공개 문서 gardens/{gid}.room.keys — 키보드가 방에 놓였을 때만
keys: Array<{ f: string; s: string; v?: number /* s가 "rec"일 때만 */ }>
```

- 옛 장부는 처음 키(새싹·하트·음표·별 + 오르골 도·미·솔·높은 도)로 채운다(`normalizeKeys`).
- 보는 쪽(`keysFromPublic`)은 그림의 길이·글자를 다시 보고, 표에 없는 소리·판 없는 녹음은 **소리 없음**으로 그린다.
- 공개 문서에는 그림·소리 id·판 번호만. 글도, 파일 주소도 싣지 않는다. 녹음 경로는 문서의 `ownerUid`와 판에서 만든다.

**녹음.**

- 키마다 1.5초까지. 마이크 권한(거절·마이크 없음·다른 앱이 씀·지원 안 함을 사람의 말로), 3·2·1 세기, 소리 크기 막대, 남은 시간 막대,
  멈추기·다시 녹음·들어 보기. 16kHz 모노 16비트 WAV(1.5초 ≈ 47KB). MediaRecorder는 쓰지 않는다(기기마다 코덱이 다르다).
- 목소리: 🤖 로봇(기본, 고리 변조) · 🐿 높은 목소리 · 🐻 낮은 목소리(빠르기를 바꿔 다시 읽기) · 🙂 원래 목소리(확인 체크).
  **올리기 전에 이 기기에서 한 번** 바꾸고 그 결과만 올린다(`room/voice.ts`의 `applyVoice`). 들어 보는 소리와 올라가는 소리는 같은 Blob이다.
  원래 녹음은 그 화면의 메모리에만 있다가 버려진다 — 원래 목소리를 고르고 확인하지 않는 한 어디에도 보내지 않는다.
  바꾼 목소리도 아는 사람은 알아챌 수 있다고 화면에 적는다("익명"이라 하지 않는다).
- 올리는 곳 `roomKeys/{uid}/{칸 0–3}-{판}.wav`. 다시 녹음할 때마다 판이 1 오르고(같은 주소를 덮으면 캐시가 옛 목소리를 준다),
  올리기가 끝난 뒤 옛 판을 지운다. 판은 녹음을 지워도 줄지 않는다.
- 방을 연 사람만 녹음한다. 녹음은 손님이 듣는 소리라서, 방을 열지 않으면 들을 사람이 없다.
- 손님 쪽 재생은 `<audio>`다. 버킷에 CORS 설정이 없어(이 저장소에 cors 파일 없음) fetch+decodeAudioData로는 다른 출처에서 읽지 못한다.
  시트를 열 때 넷을 미리 받고(`getDownloadURL`, 세션 동안 기억), 박자에 맞출 때는 남은 시간만큼 타이머로 기다린다.
  iOS가 터치 밖 재생을 막지 않게 첫 누름에서 넷을 소리 없이 한 번 틀어 둔다.

**지우기.** 읽기를 열어 둔 대가는 "정말 지운다"이다(인포그래픽·프로필 사진과 같다).

| 언제 | 누가 | 실패하면 |
|---|---|---|
| 방 공개를 끔 · 키보드를 보관함에 넣음 | 주인 화면(`room/keyCleanup.ts`)이 그 판들을 지운 뒤 키를 처음 소리로 | 키의 녹음 표시를 남겨 두고 다음에 정원을 열 때 다시 |
| 키 소리를 녹음 → 다른 소리로 저장 | 키 편집기가 파일을 먼저 지우고 저장 | 저장하지 않는다("녹음을 지우지 못해…") |
| 처음으로 되돌리기 | 키보드 시트가 다 지운 뒤 되돌림 | 되돌리지 않는다 |
| 다시 녹음 | 새 판을 올린 뒤 옛 판을 지움 | 옛 판이 **남는다(고아 파일)** |

고아 파일이 생기는 길: 다시 녹음 뒤 옛 판 지우기 실패, 녹음이 있는 채 계정을 바꾼 기기(새 계정은 옛 uid 경로를 지우지 못한다),
녹음이 있는 채 정원 장부를 지운 기기. 치우는 법은 배포 메모의 "남은 녹음 치우기".

**신고와 가리기.**

- 손님은 키보드 시트의 `🚩 신고`로 신고한다. 방명록 신고와 같이 `feedback`에 **경로만** 보낸다(`[정원 신고] 키보드(그림·소리) · gardens/{gid}/room/keys`) — 그림·소리를 다시 퍼뜨리지 않는다.
- 운영자는 그 방에 가서 키보드를 열고 `키보드 가리기`를 누른다 → `gardens/{gid}/mod/keys {hidden, at}`(규칙이 운영자만 쓰게 한다, 누구나 읽는다).
  주인의 문서와 따로 살아서 주인이 고쳐도 풀리지 않는다. 보는 화면은 이 표시를 읽고 **빈 키·소리 없음**으로 그린다(방 그림의 키보드도).
  주인은 자기 시트에서 알림을 본다. 운영자는 원래 키를 보고, `녹음 파일 지우기`로 Storage 파일도 지운다(규칙이 운영자 삭제를 받는다).
- 그림·소리의 내용은 계측하지 않는다. 이벤트는 `key_play{source: preset|rec, mine}`(시트를 열고 처음 누른 한 번만), `key_record{mode}`, `key_edit{what}`.

**청소년에게 하는 말.** 처음 녹음하기 전에 두 문장으로: "녹음한 소리는 인터넷에 올라가고, 내 방에 오는 사람은 누구나 들을 수 있어요.
이름·학교·전화번호 같은 건 말하지 마세요." 녹음 칸에도 한 줄로 남겨 둔다.

**생김새.** 속지 그대로(점선, 하늘색 제목, 주황 강조). 키캡은 굵은 먹색 테두리·아래로 두께가 있는 도트 키, 누르면 내려앉는다
(움직임 줄이기면 내려앉지 않고 그림자만). 키는 64px 이상, 다른 누름 자리 44px 이상, 360px에서 옆 넘김 없음.

### 4.6 방 한마디 (2026-11-14)

'내 방' 제목 옆 빈 칸에 방을 소개하는 한 줄(30자)을 건다. 주인이 직접 쓴다.

| 항목 | 내용 |
|---|---|
| 저장 | `room.motto`. 비어 있으면 공개 방에 싣지 않는다 |
| 걸러내기 | 방명록과 같은 것(`ilchon/text.ts` — 링크·연락처·메신저 아이디·욕). 쓸 때 막고, 남의 방을 그릴 때 다시 거른다(손으로 만든 문서) |
| 규칙 | `publicRoom()`이 문자열 30자까지만 받는다 |
| 보이는 곳 | 내 홈과 그 방을 방문한 화면뿐. 자랑 카드·미리보기·위키에는 싣지 않는다 |
| 신고·가리기 | 손님은 신고(경로만 `feedback`으로), 운영자는 `gardens/{gid}/mod/motto`로 가린다(키보드의 `mod/keys`와 같은 틀, `lib/firebase/roomMod.ts`) |



### 5.1 맺기

| 단계 | 내용 |
|---|---|
| 조건 | 둘 다 방을 열어 둔 사람(공개 id가 있어야 서로를 가리킬 수 있다) |
| 신청 | 남의 방에서 `🤝 1촌 신청` → 이름표를 고른다(씨앗 친구, 물 친구, 잡초 전우, 광장 동지, 옆 텃밭…) |
| 수락 | 받은 사람이 1촌 탭에서 수락하며 자기 쪽 이름표를 고른다. 거절하면 신청만 사라진다 |
| 끊기 | 어느 쪽이든 언제나. 상대에게 알리지 않는다. 양쪽 목록에서 함께 빠진다 |
| 상한 | 1촌 50명, 보낸 신청은 동시에 10건 |
| 보호 | "신청 받지 않기" 스위치, 차단(그 사람의 신청·방명록이 내게 오지 않는다), 쪽지 없음 |

방을 여는 것이 1촌의 문턱이라, 지금 "자랑하기" 안쪽에 숨은 공개 스위치를 홈의 첫 안내로 끌어낸다:
"방을 열면 1촌을 맺을 수 있어요 — 보이는 것은 정원 이름과 방, 텃밭뿐이에요."

### 5.2 1촌이 되면 달라지는 것

| 것 | 내용 | 상한 |
|---|---|---|
| 물 주기 | 지금은 아무 공개 정원에나 하루 5번, 남은 시간 −10%. 1촌에게 준 물은 −15% | 하루 5번 그대로 |
| 1촌 소식 | 1촌 탭 맨 위. "파란 참새 — 황금 화분을 놓았어요", "새 품종을 거뒀어요" | 1촌마다 최근 한 줄 |
| 1촌평 | 1촌의 방 첫 화면에 한 줄. 정해 둔 문구 + 스티커 | 1촌 한 명당 한 줄(다시 쓰면 바뀐다) |
| 같이 잡자 | 거대 잡초가 뜨면 1촌 탭에 "지금 싸우는 1촌 2명". 1촌과 같은 물결에서 치면 연출이 붙는다 | 보상 차이 없음 |
| 나란히 보기 | 지금의 "친구 정원과 나란히"가 1촌 목록으로 옮겨 온다 | — |

- **1촌 수에는 보상이 없다.** 많이 맺는다고 잼도 칭호도 주지 않는다. 주면 모르는 사람에게 신청을 뿌리게 된다.
- 소식은 글이 아니라 **종류 번호**다. 방 주인의 화면이 공개 문서에 `news: [종류, 품종 id, 때]`를 적고,
  읽는 화면이 문장을 만든다.
- 지금의 `friends`(가 본 정원) 목록은 "가 본 방"으로 남는다. 1촌은 그 위의 관계다.

### 5.3 방명록과 손님 수

| 것 | 내용 |
|---|---|
| 방명록 | 손님이 문구 하나와 스티커 하나를 고른다. 한 방에 하루 한 번. 주인은 지울 수 있다. 최근 30개를 보인다 |
| 문구 | 정해 둔 서른 개쯤 — "구경 잘 했어요", "황금 화분 부러워요", "같이 잡초 잡아요", "물 주고 가요" |
| 오늘 손님 / 모든 손님 | 다른 사람이 방을 열면 하루 한 번 센다. 그 방에서만 보인다 |
| 누가 왔는지 | 보이지 않는다. 방명록을 남긴 사람만 이름이 남는다 |

**자유 글을 쓸 수 있다 (2026-11-14 결정).** 방명록과 1촌평은 정해 둔 문구를 고르거나 직접 쓴다(60자까지).
모르는 사람이 내 방에 글을 남기는 자리이므로 안전 장치를 함께 둔다.

| 장치 | 내용 |
|---|---|
| 길이·횟수 | 60자, 한 방에 하루 한 번(방명록) · 1촌 한 명당 한 줄(1촌평). 규칙이 지킨다 |
| 주인 | 자기 방의 글을 지운다. 방명록 받기를 "모두 / 1촌만 / 받지 않기"로 고른다(기본 모두) |
| 신고 | 누구나 글을 신고한다. 신고는 운영자 큐(`feedback`)로 간다 |
| 운영자 | 글을 가린다(`hidden`). 지지자 응원(`cheerNotes`)의 가리기와 같은 방식을 쓴다 |
| 걸러내기 | 응원 글에 쓰는 금칙어·링크 걸러내기가 있으면 같은 것을 쓴다. 링크와 연락처 모양은 막는다 |
| 싣지 않는 곳 | 자랑 카드·미리보기·위키·전광판. 사람이 지은 글은 그 방 안에서만 보인다(소스가 아니다) |

### 5.4 마실 (파도타기 자리)

- 방명록의 이름을 누르면 그 사람 방으로 간다(그 사람이 방을 열어 두었을 때).
- 1촌 탭의 `🎲 아무 방이나` — 최근에 고쳐진 공개 방 스무 곳 중 하나.
- 꽃밭 명패의 이름에서 그 정원지기의 방으로.
- **1촌의 1촌 목록은 보이지 않는다.** 방 주인이 "내 1촌 보이기"를 켠 경우에만 방에 이름이 나온다(기본 꺼짐).
  관계망이 드러나는 것은 본인이 정한다.

### 5.5 자료와 규칙

서버 코드를 두지 않고 Firestore 규칙이 불변식을 지킨다(초대·물 주기와 같은 방식).

| 문서 | 담는 것 | 규칙이 지키는 것 |
|---|---|---|
| `gardens/{gid}/knocks/{신청자 uid}` | 신청자의 공개 id·정원 이름·이름표 번호·때 | 신청자가 그 공개 id의 주인이다. 자기 방에는 못 한다. 주인이 신청을 껐으면 못 한다. 주인과 신청자만 읽고 지운다 |
| `gardens/{gid}/ilchon/{1촌 uid}` | 1촌의 공개 id·이름 사본·이름표·맺은 때 | 수락하는 사람이 **양쪽 문서를 한 커밋으로** 쓰고 신청을 지운다. 신청이 있었을 때만. 지울 때도 양쪽이 함께 |
| `gardens/{gid}/guestbook/{손님 uid}` | 문구 번호·스티커 번호·정원 이름 사본·날 | 번호가 표 안에 있다. 남의 방에만, 하루 한 번. 주인이 지운다 |
| `gardens/{gid}/visits/{손님 uid}` + `gardens/{gid}/meta/counter` | 날 / 오늘·모두 | 표식과 숫자가 짝이 맞을 때만 1 오른다(`plazaDays`와 같은 방식) |
| `gardens/{gid}` | `room`, `news`, `accept`(신청 받기), `showIlchon` | 키와 길이. 지금 `publicGarden()`에 더한다 |

- 문서 id가 uid인 것은 지금의 `waters/{방문자 uid}`와 같다. 주인은 1촌·손님의 uid를 알게 되지만
  그것으로 읽을 수 있는 남의 문서는 없다.
- 공개를 끄면 지금은 `gardens/{gid}`를 지운다. 아래 문서(1촌·방명록)는 남는다 — **1촌이 있는 방은
  문서를 지우지 않고 `hidden: true`로 가린다.** 다시 켜면 1촌이 그대로다. 정원을 통째로 지울 때만 다 지운다.
- 읽기 비용: 1촌 탭을 열 때 1촌 문서 목록 한 번 + 1촌 방 문서 최대 50. 탭을 열 때만, 10분에 한 번.
- 계측: `ilchon_knock`, `ilchon_accept`, `ilchon_cut`, `room_visit{mine, ilchon}`, `guestbook_post`. 누구인지는 보내지 않는다.

> **구현하며 바꾼 것 (2026-11-14, 2단계).**
> - 방명록 문서 id는 `{손님 uid}_{한국 날짜 번호}`다. `{uid}` 하나면 다음 날 쓴 글이 어제 글을 덮어 방명록이 쌓이지 않는다.
>   하루 한 번은 규칙이 id로 본다(`eid == uid + '_' + 오늘`).
> - 1촌평은 `gardens/{gid}/notes/{1촌 uid}`에 둔다(표에 자리가 없었다). 1촌 문서가 있을 때만, 내 공개 id가 1촌 문서의 것과 같을 때만.
> - 차단은 `gardens/{gid}/blocks/{uid}`(주인만)에 두고, 신청·방명록 규칙이 `exists`로 본다. 화면만 거르면 차단이 아니다.
> - "내 1촌 보이기"는 1촌 문서를 열지 않고, 켰을 때만 공개 문서에 `ilchonList`(1촌의 공개 id·이름, 50개)를 싣는다 — 1촌 uid를 공개하지 않게.
> - 1촌의 물: 물 표식에 `il: true`를 적고, 규칙이 정말 1촌인지(`ilchon/{uid}` 있음) 본다. 받는 쪽은 이 표시를 믿고 15% 줄인다.
>   주는 쪽의 내 텃밭 −15%는 화면이 정한다 — 속여도 빨라지는 것은 제 텃밭뿐이다(개인 장부, 본문서 §3.12).
> - 가린 방은 `{ownerUid, hidden: true, updatedAt}`만 남는다(방·텃밭·소식을 걷어 낸다). 방명록·1촌평·손님 수 읽기도
>   가린 방이면 주인·운영자만. `/g/…`·`/api/garden-card`·놀러 가기·1촌 목록은 가린 방을 없는 방으로 다룬다.
> - 1촌 50명·보낸 신청 10건의 상한은 규칙이 세지 못해 화면이 지킨다. 넘겨서 얻는 것이 없다(1촌 수에 보상 없음).
> - 손님 수는 그 방에 온 손님에게도 보인다(그 방 안에서만, §3.2의 TOTAL 줄). 누가 왔는지는 보이지 않는다.
> - 홈 새 소식의 "1촌 소식"은 이번 세션에 1촌 탭에서 읽은 1촌 방으로 만든다 — 홈을 위해 1촌 방 50개를 따로 읽지 않는다.
> - 응원(`cheerNotes`)에는 금칙어·링크 걸러내기도, 가리기도, 신고도 없었다(길이만 본다). 그래서 가장 작은 것을 새로 둔다:
>   `ilchon/text.ts`(링크·전화번호·@아이디·메신저 이름·욕 몇 개, 화면에서), 운영자 `hidden`(규칙이 운영자만 받는다),
>   신고는 `feedback`에 **글 없이 문서 경로만**(피드백은 누구나 읽는다 — 신고가 그 글을 다시 퍼뜨리면 안 된다).

- 카드를 누르면 아래 시트: 큰 그림, 설명, 가진 수, 오늘 남은 수, **방에 놓아 보기**(가구), 사기.
- 지금은 잼이 모자라면 단추가 흐려질 뿐이다. "잼 80 더 필요해요"를 적는다.

- 씨앗 진열 확률 안내문은 🌱 칩 안의 `확률 보기`로 접는다. 지금은 긴 문단이 목록 아래에 늘 펼쳐져 있다.
- 🧪 도구의 싸움 아이템은 거대 잡초 싸움터에서도 바로 살 수 있게 한다 — 지금은 싸우다 탭을 옮겨야 한다.

### 6.2 잼의 흐름

들어오는 잼은 그대로 두고 나갈 곳을 만든다. 가구 한 벌(벽지·바닥·가구 대여섯)이 대략 대표 열매
열 개 값, 볕 드는 방이 열두 개 값이다. 오래 한 사람에게는 몇 주 치 목표가 생기고, 처음 온 사람은
첫날에 소품 하나(50잼)를 살 수 있다. 값은 잼 분포를 보고 맞춘다(`garden:stats`에 잼 분포를 더한다, §8).

## 7. 거대 잡초 2.0

### 7.1 무엇이 단조로운가

§1의 숫자대로다. 한 사람은 60방을 쓰면 끝나고, 60방은 누가 쳐도 60이다. 약점·콤보·합동 게이지는
"한 방에 몇 번 문지르나"만 줄여서 **빨리 끝나게** 할 뿐 **결과**를 바꾸지 못한다. 몫을 다 쓴 사람은
구경만 한다. 보상은 늘 같다.

지켜야 할 것도 있다. 혼자서는 못 잡는다 / 규칙이 지킬 수 있는 것만 결과에 닿는다(아이템은 내 장부에
있어 규칙이 못 본다) / 순위표는 없다.

### 7.2 세 가지를 바꾼다

**① 빈틈 — 같은 때 치면 세다.**

| 항목 | 값 |
|---|---|
| 빈틈 | 매 시 정각과 30분부터 3분 (한국 시각) |
| 효과 | 빈틈 안의 한 방은 2로 센다. 내 몫은 그대로 "기력 60번" |
| 체력 | 종류별 1.5배 — 270 · 360 · 450 |
| 뜻 | 모두 빈틈에 치면 3–4명, 아무 때나 치면 5–8명이 든다 |

- 빈틈은 **시각에서 정해진다.** 규칙이 `request.time`만으로 볼 수 있어 화면이 속일 수 없고,
  단비처럼 "정각에 모이자"는 약속이 된다(본문서 §3.2의 "같은 시각").
- 화면은 다음 빈틈까지 남은 시간을 늘 보이고, 홈의 새 소식에도 뜬다. "같이 잡자" 카드에도 적는다.
- 빈틈이 아닐 때 기력을 쓸지, 기다릴지가 선택이 된다. 급한 사람은 지금 치고(1), 약속한 사람들은 모여서 친다(2).
- 지킬 선: 도망 비율이 30%를 넘으면 체력을 먼저 되돌린다. 지금 처치 83%를 떨어뜨리려는 것이 아니다.

**② 지원 — 기력을 다 써도 할 일이 있다.**

기력과 따로, 누구나 60초마다 한 번 지원을 건다. 내 싸움 표식(`fighters/{uid}`)에 지원 종류와 때를
적고, 다른 사람의 화면이 그것을 보고 효과를 그린다. 효과는 **손맛에만** 닿는다(문지르기 수·묶임) —
센 방 수는 바뀌지 않으므로 반칙해서 얻을 것이 없다.

| 지원 | 효과 (모두에게) |
|---|---|
| 🥁 응원 북 | 20초 동안 한 방에 드는 문지르기 절반 |
| ☂️ 큰 우산 | 다음 반격 한 번을 모두가 피한다 |
| 🔦 손전등 | 30초 동안 가짜 약점이 사라지고 약점이 더 자주 뜬다 |

지원을 건 사람의 이름이 싸움터에 뜬다("파란 참새가 북을 쳤어요"). 기력을 다 쓴 사람, 늦게 와서
빈틈을 기다리는 사람이 맡는 자리다.

**③ 막판과 포자 — 흐름에 굴곡을 둔다.**

| 장치 | 내용 |
|---|---|
| 폭주 | 도망 30분 전부터 반격이 잦아지고, 그 대신 **빈틈이 3분 → 6분**(규칙이 시각으로 본다). 막판 뒤집기 |
| 포자 | 체력이 절반이 되면 광장 칸에 포자 잡초 여섯이 돋는다. 모두 뽑으면 다음 빈틈 동안 문지르기 절반. 싸움터와 광장이 이어진다 |
| 단계 | 지금의 75·50·25% 단계와 종류별 성질(방패·덩굴·가짜 약점)은 그대로 둔다 |

### 7.3 아이템

지금 3종 → 세 묶음 9종. 모두 잼, 정해진 값, 하루 상한. 무작위 없음.

| 묶음 | 아이템 | 하는 일 | 값 · 하루 |
|---|---|---|---|
| 공격 | ⛏️ 곡괭이 / 🌪️ 회오리 / ☀️ 햇살 폭발 | 기력 5·10·20번을 한 번에 (지금 그대로). 빈틈에 쓰면 그것도 2배 | 20·45·100 · 6·3·1 |
| 지원 | 🥁 북채 / ☂️ 우산살 / 🔋 건전지 | 그 지원의 기다림 60초 → 20초, 물결 하나 동안 | 각 30 · 3 |
| 버티기 | 🧤 가죽 장갑 | 반격에 맞아도 한 번은 묶이지 않는다 | 25 · 5 |
| 버티기 | ⏰ 자명종 | 다음 빈틈 1분 전에 화면이 울린다(탭이 열려 있을 때) + 빈틈 시각을 내 캘린더에(익음 알림과 같은 길) | 15 · 3 |
| 버티기 | 🧃 잼 주스 | 콤보가 끊기는 쉼 2.5초 → 6초, 물결 하나 동안 | 20 · 3 |

"기력을 더 주는" 아이템은 만들지 않는다. 규칙이 산 것을 볼 수 없어서, 만들면 혼자 잡는 길이 열린다.

| 악초 표본 | 쓰러뜨릴 때마다 그 종류의 표본 조각 1 | 같은 종류 셋이면 그 악초의 **박제**(방 전시품) 확정 |
| 여섯 악초 | 여섯 종류 박제를 다 모았다 | 벽지 "광장을 지킨 방" |
| 도망 | 못 잡았다 | 상자 없음(지금 그대로). 친 사람에게 뿌리 조각 1 — 빈손은 아니게 |

- **뿌리 조각**은 거대 잡초에서만 나오는 두 번째 재화다. 상점 🏆 전리품에서 한정 가구·벽지·필살기
  연출로 바꾼다. 잼으로 살 수 없고 남에게 줄 수 없다. 재화를 하나 더 두는 까닭은, 잼만 주면 텃밭이
  더 싸게 주는 것을 또 주는 셈이라 싸울 이유가 되지 못해서다.
- 빠른 처치 ★은 물결 문서의 두 시각(태어난 때·쓰러진 때)으로 정해지므로 모두 같고 속일 수 없다.
  "끝까지"·"응원단"은 내 싸움 표식으로 본다.
- **가장 많이 친 사람은 뽑지 않는다.** 모두 기력 60이라 뜻이 없고, 순위는 두지 않는다(§1).
  쓰러뜨린 뒤에는 "함께한 사람들"의 이름을 한 화면에 올린다 — 친 사람과 지원한 사람을 같은 줄에.
- 칭호 "잡초 사냥꾼"은 그대로. 지원 칭호는 쓰임을 본 뒤에 더한다.

> **구현하며 바꾼 것 (2026-11-14, 3단계 — 거대 잡초 2.0).**
> - **수치(한 곳):** 서버와 짝인 값은 `rules.ts`(빈틈 `RAID_GAP_EVERY 30`·`RAID_GAP_MINUTES 3`·폭주 `RAID_FRENZY 30분`·`RAID_FRENZY_GAP_MINUTES 6`·
>   `RAID_GAP_MULT 2`·기력 `RAID_USES_PER_PERSON 60`·하한 `RAID_HP_MIN 270`·지원 `RAID_AID_MIN_GAP 20초`·이름 `RAID_NAMES_PER_SHARD 30`),
>   화면만의 값은 `raid/rules.ts`(아이템·★ 기준 30/90분·조각 3/2/1·+1·+1·도망 1·표본 3·포자 6). 체력은 270·270·360·360·450·450.
> - **빈틈 2배는 체력 270 이상인 물결에만** 준다(규칙도 `raid.hp >= 270`). 배포하는 날 이미 떠 있는 체력 180 물결을 둘이 빈틈에 잡지 못하게.
> - **지원을 남이 보는 길:** 표식(`fighters/{uid}`)은 본인만 읽고, 모두를 읽게 열면 한 방마다 읽기가 두 배가 된다. 그래서 지원은 내 표식(간격·횟수를
>   규칙이 본다)과 **내 칸**(`shards/{n}`의 `aid·aidAt·aidBy`, 마지막 하나)에 함께 적는다. 모두가 이미 칸 여덟을 구독하므로 새 구독이 없다.
>   지원 한 번 = 보는 사람마다 읽기 1. 같은 칸의 지원이 1초 안에 겹치면 앞의 것이 화면에 안 뜰 수 있다(효과만 손맛이라 감당한다).
> - **함께한 사람들:** 칸에 `names`(처음 드는 커밋에서 정원 이름 한 줄, 칸마다 30)를 둔다. 옛 화면은 칸을 통째로 쓰므로 이름이 지워질 수 있고,
>   화면은 `fighters − 이름 수`를 "이름 모를 정원지기 N명"으로 적는다. 정원 이름은 이미 꽃밭 명패에도 공개되는 이름이다.
> - **응원단은 "세 번 넘게"가 아니라 "세 번 이상"**(브리프). 지원만 한 사람도 표식이 생겨 참여 인원에 들고 상자를 받는다.
> - **자명종:** 캘린더 넣기(빈틈·단비)는 §8의 6에 따라 누구나 쓰는 알림으로 두고, 자명종은 "켠 물결 동안 빈틈 1분 전마다 탭에서 울림"만 맡는다.
>   밤 22–8시의 빈틈은 캘린더 단추를 띄우지 않는다.
> - **가죽 장갑**은 맞는 순간 저절로 하나 쓴다(고르는 단추를 두면 반격 경고 1.6초 안에 누를 것이 둘이 된다).
> - **빈틈 판단은 이 기기 시계 → 규칙이 서버 시각으로 다시 본다.** 가장자리 20초 안에서 막히면 반대 값으로 한 번 더 보낸다(`lib/firebase/raid.ts`).
> - **상자 확률:** 굴림 값 r이 `1 − 다년생 확률` 이상이면 다년생이다. ★★★(35%)은 다년생 쪽만 넓히므로 20%에서 다년생이던 상자는 그대로이고,
>   ★/★★ 상자는 2.0 전과 똑같은 씨앗이다. 연 상자는 장부(`raids`)가 다시 열지 않고 별은 쓰러진 뒤 바뀌지 않는다.
> - **보상 장부:** 쓰러뜨린 물결은 지금처럼 `raids`(칭호 "잡초 사냥꾼"도 이것을 센다), 도망간 물결의 조각은 `loot.fled`. 둘 다 `raidKey`로 한 번만.
>   뿌리 조각은 `roots`, 표본은 `loot.samples`, 박제는 방의 전시품(`kind: "trophy"`, `species`에 악초 종류 id, 벽·바닥 어디든).
>   공개 방에는 `{a, k: "trophy", s: 종류}`만 싣는다 — `firestore.rules`의 방 검사는 그대로(목록 길이만 본다).
> - **전리품 진열(뿌리 조각):** 광장 깃발 5 · 응원 북 6 · 광장 등불 8 · 광장 돌바닥 8 · 덩굴무늬 벽지 10 · 광장 벤치 12 · 전리품 진열장 15 ·
>   꽃잎 필살기 20 · 작은 분수 25 · 별빛 필살기 30. 보상 벽지 "광장을 지킨 방"은 팔지 않는다.
> - **포자**는 광장 칸 위에 얹는 그림이고 서버에 아무것도 쓰지 않는다. 이 기기에서만 세고, 효과는 내 문지르기뿐이다.

**순서: 규칙 먼저, 화면은 그 뒤.** 새 화면은 표식에 `uses·aid·aidAt·aids`, 칸에 `names·aid·aidAt·aidBy`를 적는다.
지금 배포된 규칙은 이 키를 받지 않으므로(`hasOnly`) 화면이 먼저 나가면 **모든 타격이 거절된다.**
새 규칙은 옛 화면의 모양을 그대로 받으므로 규칙을 먼저 내도 싸우던 물결이 끊기지 않는다.

| 것 | 할 일 |
|---|---|
| `firestore.rules` | `plazaRaids` 절 전체(`raidMove`·`raidOldStrike`·`raidGap`·`raidShardExtras`·`raidLive`·`raidPath`). `firebase deploy --only firestore:rules` |
| 점검 | 배포 전 `firebase emulators:exec --only firestore --project demo-jamtong "pnpm check:raid-rules"`(분 3–5·33–35에 돌리면 빈틈 두 갈래가 다 나온다, `RAID_RULES_WAIT=1`). 배포 뒤 `pnpm check:rules`(운영, 옛 모양의 길이 열려 있는지) |
| 색인 | 새로 만들 것 없다. 홈의 오늘 물결 읽기는 `__name__` 범위 질의라 자동 색인이다 |
| 화면 | 규칙 다음에 배포 |

**지금 열려 있는 옛 화면(규칙만 바뀐 동안·배포 뒤 새로고침 전)**

| 옛 화면이 하는 것 | 새 규칙에서 |
|---|---|
| 한 방 `{hits+1, lastAt, shard}` + 칸 `{hits, fighters}`(set) | 통과. `uses`가 없으면 기력 = 센 값, 빈틈과 상관없이 1:1, 60까지(`raidOldStrike`). 칸의 이름·지원이 지워질 수 있다(연출만) |
| 필살기 +5·10·20(uses 없음) | 통과. 1:1 |
| 칸 이전(11-06 전) 탭의 물결 문서 +1 | 통과(옛 길을 남겼다 — 아래) |
| 새 물결 세우기(체력 180·240) | **막힌다**(하한 270). 300(갑질·땅투기)은 통과. 옛 화면은 다시 시도하지 않고 콘솔에 남긴다. 새 화면이 하나라도 광장에 있으면 그쪽이 세운다. 옛 화면만 남은 시간에는 그 물결이 늦게 나온다 — 피할 수 없는 깨짐은 이것뿐이다 |
| 쓰러뜨리기 | 그대로(칸 8 + 물결 문서의 합) |
| 배포하는 날 이미 떠 있던 물결(체력 180–300) | 계속 싸운다. 체력 270 아래면 빈틈 2배가 없다(규칙·화면 같음) — 둘이 잡지 못하게. 그 물결의 상자는 받고, ★ 조각도 받는다 |
| `/api/raid-card`·`/r/…` | 물결 문서와 칸의 `hits·fighters`만 읽는다. 칸에 새 키가 붙어도 그대로 |

**옛 길(물결 문서 직접 +1)을 남긴 까닭.** 칸 이전 화면은 막히면 1.2초마다 끝없이 다시 보낸다(git `7cb26ae`의 `useRaid`). 그런 탭이 아직 열려 있는지는
운영 데이터를 보지 않고는 알 수 없고(`UpdateNotice`는 새로고침을 권하기만 한다), 남겨 둬도 불변식에 닿지 않는다 — 한 사람 60·1:1·물결 문서 ≤ 체력.
`pnpm garden:stats`가 이제 "옛 길로 들어온 물결 — 11-07 이후 N"을 찍는다. 몇 주 0이면 그 `allow update`와 표식의 `shard` 없는 갈래를 지운다.

**되돌리기.** 처치율이 70% 아래로 내려가거나 도망이 30%를 넘으면 `RAID_KINDS`의 체력을 낮춘다 — 하한(270)보다 낮추려면 규칙의 `hp >= 270`과
`raidGap`의 `raid.hp >= 270`, `RAID_HP_MIN`을 함께 고친다(`raid.test.ts`가 짝을 본다). 하한을 240 아래로 내리면 둘이 빈틈에 잡을 수 있게 된다.

## 배포 메모 (내 키보드, 2026-11-14)

**순서: Firestore 규칙 → Storage 규칙 → 화면.** 새 화면은 공개 방에 `room.keys`를 싣는다. 지금 배포된 `publicRoom()`은 `keys`를 받지 않으므로(`hasOnly`)
화면이 먼저 나가면 키보드를 놓은 사람의 공개가 모두 거절된다. Storage 규칙이 없으면 녹음 올리기가 "그 밖의 모든 것은 닫는다"에 막힌다.
새 규칙은 옛 화면의 모양(키 없음)을 그대로 받는다.

| 것 | 할 일 |
|---|---|
| `firestore.rules` | `publicRoom()`의 `keys`, `publicKeys()`·`publicKey()`, `gardens/{gid}/mod/{docId}`. `firebase deploy --only firestore:rules` |
| `storage.rules` | `roomKeys/{uid}/{fileId}`(읽기 열림, 제 uid 경로에만 새로 올리기·`audio/wav`·64KB 아래·덮어쓰기 없음, 주인·운영자 지우기). `firebase deploy --only storage` |
| 버킷 CORS | **바꿀 것 없다.** 재생은 `<audio>`, 주소는 `getDownloadURL`(인포그래픽과 같은 길)이라 CORS가 들지 않는다 |
| 색인 | 새로 만들 것 없다(`mod/keys`는 문서 하나 읽기) |
| 점검 | 배포 전 `firebase emulators:exec --only firestore --project demo-jamtong "pnpm check:ilchon-rules"`(공개 방의 키·가리기 포함)와 `firebase emulators:exec --only firestore,storage --project demo-jamtong "pnpm check:storage-rules"` |
| 계측 | `key_play`·`key_record`·`key_edit` — 새 이벤트라 GA 쪽 설정은 없어도 된다 |
| 화면 | 규칙 둘 다음에 배포 |

**남은 녹음 치우기(운영자).** 화면이 지우지 못한 파일은 이렇게 찾는다 — `gsutil ls 'gs://<버킷>/roomKeys/**'`의 각 `roomKeys/{uid}/{칸}-{판}.wav`가,
`gardens`에서 `ownerUid == uid`이고 숨기지 않은 문서의 `room.keys[칸]`이 `{s: "rec", v: 판}`인 경우에만 쓰이는 파일이다. 그 밖의 파일은 지워도 된다
(`gsutil rm`, 또는 콘솔). 운영 데이터를 건드리는 일이라 스크립트로 두지 않았다 — 필요해지면 `firebase-admin`으로 읽기 전용 목록을 먼저 뽑아 사람이 확인한다.


### 키보드 여러 개의 저장

키보드마다 고정 개체 번호(`placed[].kb`, 0–8)를 붙인다. 0번의 키는 기존 `room.keys`, 나머지는 `room.keyboards`에 저장한다. 이동할 때 번호를 유지하고 보관함에 넣어도 그림과 기본 소리 설정을 보존한다. 다시 놓을 때 비어 있는 가장 작은 개체 번호부터 꺼낸다. 예전 방의 여러 키보드는 기존 키를 각각 복사해 독립시킨다.

공개 방도 배치의 개체 번호와 놓인 키보드들의 키만 싣는다. 추가 키보드는 `그림:소리:판;` 네 토막으로 압축해 규칙의 계산 한도 안에서 전부 검사한다. 녹음 판은 방 전체의 최댓값보다 큰 번호를 써서 키보드끼리 파일 주소가 겹치지 않게 한다. 예전 방에서 복사된 녹음은 다른 키보드의 참조가 남아 있으면 삭제하지 않는다. 공개를 끄거나 해당 키보드를 치울 때 녹음 표시를 지우고, 남은 참조가 없는 파일만 삭제한다.
