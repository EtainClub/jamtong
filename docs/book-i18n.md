# 자서전 일본어·영어 제공

> 상태: **1~8장 구현 (2026-11-20).** 『이재명 자서전』 여덟 장 전부를 일본어·영어로 옮겼다(`/ja/books/autobiography`, `/en/books/autobiography`).
> 기계 번역이고 원어민 검수 전이다.
> 결정: 중국어(간체)는 미룬다. 본토에서 유튜브·구글·Firebase가 막혀 이 사이트로는 전달할 수 없다(§5).
> 일본어와 영어부터 한다. 사이트 구조는 지금대로 둔다(`docs/garden-first-redesign.md` 결정).

## 0. 구현된 것과 다음 장 넣는 법

| 무엇 | 어디 |
|---|---|
| 번역 스키마·맞대기·지문 | `src/content/books/i18n.ts` |
| 번역 목록·주소·hreflang | `src/content/books/translations.ts` |
| 1~8장 번역 | `src/content/books/auto_2025/i18n/{ja,en}.ts`, `i18n/{ja,en}/NN.md` |
| 화면 글자(한·일·영) | `src/features/books/ui.ts` — 한국어 값은 원래 글자 그대로 |
| 옮긴 장·목차·카드 | `src/app/[locale]/books/[slug]/…` (`ja`·`en` 밖은 404) |
| 일본어 카드 서체 | `assets/fonts/NotoSansJP-{Light,Medium}.otf` (JIS X 0208로 줄임) |
| 언어 링크·hreflang | 한국어 장 페이지, 옮긴 장 페이지, `sitemap.ts` |
| 검사 | `pnpm validate` — 원본과 id·도형이 맞는가, 옮긴 인용이 옮긴 본문에 있는가(실패). 원문 변경·검수 전(경고) |

**다음 장을 옮길 때:**
1. `i18n/<언어>/NN.md`에 본문을 옮긴다(빈 줄로 문단, 소제목은 `## `).
2. `i18n/<언어>.ts`의 `chapters`에 장을 더한다. 토막은 원본 id 전부, 도형이 있으면 같은 종류로. 할 일은 옮길 수 있는 것만.
3. `basedOn`은 `pnpm validate` 경고가 알려 주는 지문을 적는다. 처음 넣을 때는 아무 12자리 hex를 넣고 경고에 나온 값으로 바꾼다.
4. 원어민이 원문과 대조하면 `review: { method, reviewed: true, reviewedBy, reviewedAt }`.
5. 일본어 카드에 JIS X 0208 밖의 한자가 나오면 서체를 다시 줄인다(`assets/fonts/README.md`).

**구현하며 정한 것:**
- 번역은 3인칭(著者 / the author)으로 옮긴다. 원본 요약은 주어를 생략했는데, 일본어·영어로 1인칭을 세우면 저자의 목소리를 지어내게 된다.
- 한자를 확인하지 못한 고유명사(예안면 도촌리 지통마을, 삼계초등학교, 사람 이름 대부분)는 일본어에서 가타카나로 적었다.
- 3인칭으로 옮기면 저자만의 주장(대장동 환수액, 20억 회유와 협박, 압수수색 횟수 등)이 편집부의 단정처럼 읽힌다.
  그런 문장에는 "according to the author" / "著者によれば"를 붙였다. 원본 토막이 "저자의 설명"으로 옮긴 것과 같은 규율이다.
- 3장의 자살 시도 대목은 방법(약의 개수, 연탄)을 옮기지 않았다. 원본 토막도 방법을 적지 않는다.
- 할 일의 링크가 그 언어 독자에게 쓸모없으면 바꿀 수 있다(`actions[id].href`). 3장의 상담 전화는 한국의 109 대신
  영어는 findahelpline.com, 일본어는 후생노동성 「まもろうよ こころ」로 바꾸고, 본문에 "한국에서는 109"를 남겼다.
- 이미지 라우트(opengraph-image)의 generateStaticParams는 부모 [locale]의 params를 받지 못한다. locale까지 통째로 낸다
  — 거르면 빈 목록이 되어 프로덕션에서 카드가 모두 404가 된다(dev 서버에서는 드러나지 않는다).
- 옮긴 장에는 사이트 하단 탭과 카카오톡 공유를 두지 않는다. 할 일 블록에는 "링크는 한국 제도, 한국어 페이지"라고 밝힌다.
- 영상: 이 언어의 영상이 없으면 "준비 중"으로 둔다. 한국어 영상을 그대로 걸지 않는다. 언어별 영상은 번역 파일의 `shorts`에 id만 넣는다.
- `<html lang="ko">`는 그대로다. `[locale]` 레이아웃이 `display: contents` 감싸개에 `lang`을 달고, `globals.css`가 `[lang="ja"]`에 일본어 글꼴을 준다.

**남은 것:** 원어민 검수(일·영), 일본어·영어 영상, 공식 일본어·영어판 존재 여부 확인(있으면 책 제목을 그 번역서 제목으로).

## 1. 지금 구조에서 확인한 것

| 항목 | 현재 | 번역에 주는 뜻 |
|---|---|---|
| 장 데이터 | `chapters.ts`(판단: 한 줄 소개·쉽게 보기 토막·할 수 있는 일·숏츠) + `text/NN.md`(요약 본문) | 번역할 덩어리가 이미 장·토막·행동 id로 잘려 있다. id를 키로 번역 파일을 붙이면 된다 |
| 본문 성격 | `bodyKind: "summary"` — 우리가 쓴 요약이고, 저자의 문장이 아니다 | **우리 요약을 번역하는 것이므로 원서 번역권 문제가 작다.** `excerpt`(저자 문장)는 번역하지 않는다 |
| 불변식 | 토막의 `quote`가 `body`에 그대로 있어야 빌드가 통과한다 | 번역본에서도 같은 언어 안에서 지킨다(번역 quote ⊂ 번역 body) |
| 도형 | `figure-fit.ts`가 글자 폭을 어림한다. 한글 1em, 라틴 0.6em | 한자·가나도 1em에 가까워 그대로 맞는다. 다만 번역문 길이가 달라 **칸 넘침 검사를 언어별로 다시 돌려야 한다** |
| 숏츠 | 장마다 `shorts: { youtubeId }[]`, 자서전 8편 | 언어별 영상 id를 따로 둘지, 같은 영상의 자막 트랙을 쓸지 정해야 한다(§4) |
| 루트 레이아웃 | `<html lang="ko">` 고정 | 일본어·중국어 페이지에 언어 표시가 필요하다(§3) |
| 웹 글꼴 | Pretendard(한글·라틴, KS X 1001 한자). 나머지는 시스템 글꼴 | 가나와 간체자는 시스템 글꼴로 넘어간다. `lang`이 없으면 한자가 한국식 자형으로 보인다 |
| OG 카드 | `assets/fonts/Pretendard-*.otf`만으로 satori가 그린다 | **가나와 간체자가 빈칸(두부)으로 나온다.** Noto Sans JP/SC 서브셋을 더해야 한다 |
| 할 수 있는 일 | 한국 독자용이다(상담 전화 `tel:`, 한국어 업적 페이지 링크) | 그대로 옮기면 외국 독자에게 맞지 않는다(§2.3) |

## 2. 데이터 설계

### 2.1 번역 파일

원본 옆에 언어별 파일을 둔다. 한국어 파일은 건드리지 않는다.

```
src/content/books/auto_2025/
  chapters.ts            ← 원본(한국어). 바꾸지 않는다
  text/NN.md
  i18n/
    ja.ts                ← { book, chapters: { [chapterId]: ChapterTranslation } }
    ja/text/NN.md        ← 번역 요약 본문
    zh-Hans.ts
    zh-Hans/text/NN.md
```

`ChapterTranslation`은 원본 id에 매달린다.

- `title`, `summary`, `easy.lead`
- `points[pointId]` — `title`, `say`, `quote?`, `figure?`
- `actions[actionId]?` — 선택(§2.3)
- `shorts?` — 언어별 영상(§4)
- `translation` — `{ by: "editorial" | "machine+review", reviewedBy?, reviewedAt?, basedOn }`

`basedOn`은 번역할 때의 원본 내용 해시다.

### 2.2 검사 (`validateBook`에 더한다)

1. **번역 파일의 모든 id가 원본에 있다.** 원본에서 지운 토막이 번역에만 남지 않게 한다.
2. **원본에 있는 토막은 번역에도 모두 있다.** 장 단위로 다 있거나 아예 없거나 둘 중 하나다.
   일부만 번역된 장은 그 언어로 공개하지 않는다. 한 페이지에 한국어가 섞여 나오지 않게 하려는 것이다.
3. 번역 quote가 번역 body 안에 있다.
4. 번역 도형이 `checkFigure`를 통과한다.
5. **원본이 바뀌면 경고한다.** 원본 장의 해시가 `basedOn`과 다르면 "번역이 낡았다"고 알린다.
   업적 쪽 `verified`와 같은 생각이다. 낡은 번역을 최신인 척 두지 않는다.

### 2.3 "할 수 있는 일"

이 섹션의 핵심은 행동 지침이다. 하지만 지금 행동은 한국 시민을 위한 것이다.

- **권고:** 번역에서는 `actions`를 선택으로 한다. 옮길 수 있는 행동만 옮긴다.
  한국어 링크에는 "(한국어)"를 붙인다. 하나도 없으면 그 자리에 "원문(한국어)으로 읽기"와 관련 업적 링크만 둔다.
- 스키마의 "행동이 없는 장은 공개하지 않는다"는 한국어 원본에만 걸린다.

### 2.4 번역 표시

화면 맨 위에 늘 적는다.

- 잼통 편집부가 우리말 요약을 옮긴 것이다. 원서의 번역본이 아니다.
- 기계 번역 후 검수했다면 그렇게 밝힌다. 검수 전이면 "검수 전"이라고 적는다.
- 원문(한국어) 장으로 가는 링크.

고유명사는 용어집 하나로 맞춘다(`i18n/glossary.ts`). 예: 이재명 → 李在明 / 李在明(イ・ジェミョン), 성남 → 城南,
소년공, 기본소득처럼 장마다 다시 나오는 말.

## 3. 주소와 렌더링

**주소:** 언어를 앞에 붙이는 하위 경로로 한다.

```
/books/autobiography/<chapter>          한국어(지금 그대로)
/ja/books/autobiography/<chapter>
/zh/books/autobiography/<chapter>       간체·번체를 정한 뒤 /zh-hans·/zh-hant 고려
/ja/books/autobiography                 번역된 장만 나오는 목차
```

- 나중에 업적 쉬운 설명을 옮길 때도 같은 틀로 `/ja/achievement/<slug>`를 쓸 수 있다.
- `Accept-Language`로 자동 리다이렉트하지 않는다. 같은 주소가 사람마다 다르게 보이면 안 되고
  (홈 렌더링 원칙과 같다), 구글도 자동 리다이렉트를 권하지 않는다.
  대신 한국어 장 페이지에 `日本語 · 中文` 전환 링크를 둔다.

**`<html lang>`:** Next 문서(`node_modules/next/dist/docs/01-app/02-guides/internationalization.md`)의 정석은
모든 라우트를 `app/[lang]` 아래로 옮기는 것이다. 사이트 전체를 번역하지 않으므로 과하다. 두 단계로 간다.

1. **처음:** `app/[locale]/books/...`만 만든다. 그 페이지의 본문 감싸개에 `lang="ja"` / `lang="zh-Hans"`를 단다.
   글꼴 선택과 화면 낭독기는 요소의 `lang`으로 충분히 맞는다.
   CSS는 `:lang(ja)`, `:lang(zh-Hans)`에 시스템 글꼴 스택(Hiragino Sans / Noto Sans JP, PingFang SC / Noto Sans SC)을 준다.
2. **번역 범위가 넓어지면:** 라우트 그룹으로 루트 레이아웃을 둘로 가른다.
   `app/(ko)/layout.tsx`는 `lang="ko"`, `app/(intl)/[locale]/layout.tsx`는 그 언어로 둔다.
   주소는 바뀌지 않는다. 대가는 두 레이아웃을 오갈 때 전체 페이지를 다시 불러오는 것뿐이다.

`[locale]`은 `generateStaticParams`로 `ja`·`zh`만 허용한다. 그 밖의 값은 404로 보낸다. `/achievement` 같은 기존 최상위 경로와 부딪히지 않게 하려는 것이다.

**SEO:**
- 세 언어 페이지가 서로를 `alternates.languages`(hreflang)로 가리킨다. 각 페이지의 canonical은 자기 자신이다.
- `sitemap.ts`에 번역 장을 더하고 `alternates`를 붙인다. 번역이 완결된 장만 넣는다.
- 일본은 구글이 주 검색엔진이라(Yahoo! JAPAN도 구글 결과) 지금 서치 콘솔로 충분하다.

**OG 카드:** `src/lib/og/card.tsx`의 글꼴에 Noto Sans JP/SC를 더한다. 쓰는 글자만 서브셋으로 넣어 크기를 줄인다.
번역 장의 `opengraph-image`는 번역 제목으로 그린다.

## 4. 영상

두 방식이 있다.

| | 같은 영상에 자막 트랙 | 언어별 영상 따로 |
|---|---|---|
| 만드는 일 | 자막(SRT)만 | 더빙 또는 화면 자막 다시 굽기 |
| 숏츠 | **숏츠 화면에는 자막 트랙이 잘 안 보인다.** 사실상 화면 자막을 구워야 한다 | 맞다 |
| 데이터 | `youtubeId` 그대로, 임베드에 `cc_lang_pref=ja&cc_load_policy=1` | 번역 파일 `shorts`에 언어별 id |
| 채널 | 한 채널 | 한 채널이나 언어별 채널 |

장 영상이 숏츠 형식이라면 **언어별 영상을 따로 두는 쪽**이 맞다. 데이터는 이미 그 모양이다(`bookShortSchema`). 번역 파일의 `shorts`에 id만 넣으면 된다.

## 5. 중국어 — 먼저 정할 것

"중국에서 인기"가 어디를 뜻하는지에 따라 할 일이 크게 다르다.

| | 중국 본토 | 대만·홍콩·해외 화교 |
|---|---|---|
| 글자 | 간체(`zh-Hans`) | 번체(`zh-Hant`) |
| 유튜브 | **차단.** 장 영상이 재생되지 않는다 | 된다 |
| 구글 검색 | 차단. 바이두가 주 검색엔진이다 | 구글 |
| 사이트 접속 | Firebase SDK(`googleapis.com`)와 GA가 막힌다. 페이지 자체가 열리는지도 실제로 확인해야 한다 | 문제 없음 |
| 영상 유통 | 빌리빌리·더우인 같은 현지 플랫폼에 따로 올려야 한다 | 유튜브 그대로 |

- 본토가 목표라면 이 사이트의 장 페이지는 "본문 읽기" 용도로만 기대하는 것이 현실적이다.
  영상은 현지 플랫폼 링크로 대신한다. 그 경우 데이터에 `youtubeId` 말고 `externalUrl`이 필요하다.
- 첫 단계는 **일본어 먼저**를 권한다. 기술 장애가 없고, 위 틀을 한 번 다 돌려 볼 수 있다.

## 6. 순서

1. 정할 것: 중국어 대상(본토 간체 / 대만·홍콩 번체), 번역 검수자(원어민), 영상 방식.
   공식 일본어·중국어판 자서전이 있는지도 확인한다. 있으면 책 제목은 그 번역서 제목을 쓰고 서지로 잇는다. 지금은 확인하지 않았다.
2. 스키마·검사: 번역 파일 타입, `validateBook` 다섯 검사, 용어집.
3. 일본어 1장만 번역해 `/ja/books/autobiography/<1장>`을 끝까지 만든다.
   페이지, 전환 링크, hreflang, 사이트맵, OG 카드, `:lang` 글꼴까지 포함한다.
4. 나머지 일곱 장과 일본어 영상.
5. 중국어(§5 결정에 따라).
6. 넓힐 때: 숏츠(`docs/shorts`), 업적 쉬운 설명. 그 무렵 루트 레이아웃 분리(§3-2)를 검토한다.
