# 거대 잡초 3.0 — 보스 레이드 설계

> 상태: 설계(2026-11-15). 구현 전이다. 앞선 설계는 `docs/garden-game.md` §3.8(1.0),
> `docs/garden-miniroom.md` §7(2.0). 이 문서는 그 위에 얹는다.

## 0. 한 줄 요약

거대 잡초를 **세 번 변신하는 보스**로 바꾼다. 빨리 잡을수록 더 센 형태로 변신하고(사람이 늘면
저절로 어려워진다), 형태가 오를수록 패널을 넘어 화면 전체로 자란다. 사람은 **역할 셋**(낫잡이·
돋보기꾼·울타리지기) 중 하나를 맡고, 보스는 세 게이지가 다 차야 쓰러진다.

지키는 것은 그대로다. 혼자·둘이서는 못 잡는다 / 규칙이 볼 수 있는 것만 결과에 닿는다 /
순위표·무작위 보상 없음 / 서버 코드 없음(Firestore 규칙만) / 특정 사람·정당·집단을 그리지 않는다.

## 2. 보스 그림 — 리그와 세 형태

### 2.1 방향

- "얄밉게"를 버리고 **RPG 보스처럼 세게** 그린다(2026-11-15 결정 — 아이가 하는 게임이 아니다).
  어둡고 위협적이어도 된다. 하지 않는 것은 하나, **피가 튀는 것 같은 유혈 표현**이다. 맞는 연출은
  갑옷 파편·수액 빛·불씨·포자로 그린다. `RaidWeedArt.tsx` 머리말의 "아이가 보는 화면이라"는 지운다.
- `RAID_KINDS`의 이름·대사와 "특정 사람·정당·집단을 가리키지 않고 행동만 잡초로 삼는다"는 원칙은 그대로다.
- 기술은 지금처럼 **SVG + CSS**, 입자만 캔버스 하나. 새 라이브러리를 들이지 않는다.
- 박제(`RaidTrophyArt`)·상점·방 전시는 1형 그림의 정지 모습을 쓴다. 3형까지 잡으면 받는 "각성 박제"는 3형 그림.

### 2.2 리그

그림 한 장을 **겹(layer)과 관절**로 나눈다. 겹마다 따로 움직여 살아 있는 덩치로 보인다.

| 겹 (뒤 → 앞) | 내용 | 움직임 |
|---|---|---|
| 오라 | 방사형 그라데이션·맥동하는 문양 | 형태마다 색·크기. 빈틈이면 꺼지고 폭주면 붉어진다 |
| 뒤 팔다리 | 덩굴·가시 날개·뿌리 | 느린 흔들림(관절마다 `transform-origin`) |
| 몸통 | 갑옷 판(부위 파괴 대상)과 속살 | 숨쉬기. 갑옷 게이지에 따라 판이 하나씩 깨져 떨어진다 |
| 머리 | 가면·뿔·왕관, 눈빛 | 손 닿은 쪽을 본다. 대기술 예고 때 눈이 탄다 |
| 앞 팔다리·무기 | 내리치는 팔, 휘감는 덩굴 | 대기술 동작(들어 올림 → 내리침) |
| 앞 입자 | 포자·불씨·금가루·말풍선 조각 | 캔버스 2D, 60개 이하 |

- viewBox 240×240(지금의 두 배 해상). 형태 하나 6KB 안팎, 종류별 파일을 `next/dynamic`으로 그 물결 것만 읽는다.
- 움직이는 것은 `transform`·`opacity`뿐이다. `feGaussianBlur` 같은 필터는 쓰지 않고 빛은 그라데이션으로 그린다 — 저가 폰에서 버티려면.
- `prefers-reduced-motion`과 정원 설정의 "연출 줄이기"에서는 정지 그림 + 형태 교체만. 지금 CSS의 전체 끄기 규칙을 그대로 탄다.

### 2.3 형태 (종류 × 3)

| 종류 | 1형 | 2형 — 각성 | 3형 — 최종 | 3형의 영역 침범 |
|---|---|---|---|---|
| 악플 가시풀 | 가시풀 | 자판 갑주 가시풀 | 익명의 가시 군주(얼굴 없는 가면, 말풍선 날개) | 화면 가장자리에서 가시가 안으로 돋는다 |
| 혐오 쐐기풀 | 쐐기풀 | 불씨 쐐기풀 | 갈라치는 쌍두 쐐기(머리가 둘로 갈라진다) | 화면을 좌우 둘로 가르는 불길 금 |
| 가짜뉴스 덩굴 | 덩굴 | 속보 덩굴(확성기 꽃) | 천 개의 입 카더라(가짜 본체 분신) | "속보" 띠가 화면을 가로질러 흐른다 |
| 검은돈 독초 | 독초 | 금고 독초(금 갑옷) | 황금 가면 독룡 | 금화가 위에서 쏟아져 화면 아래에 쌓인다 |
| 갑질 엉겅퀴 | 엉겅퀴 | 왕관 엉겅퀴 | 옥좌의 폭군(키가 패널 위로 솟는다) | 머리가 화면 위 끝을 넘고 그림자가 전체를 덮는다 |
| 땅투기 칡 | 칡 | 울타리 칡 | 광장을 삼키는 칡 거수 | 덩굴이 체력바·광장 칸·단추를 감는다 |

### 2.4 커지기 — 세 단계의 무대

| 단계 | 무대 | 구현 |
|---|---|---|
| 1형 | 패널 안. 지금 크기의 1.0배 | 지금 구조 |
| 2형 | **패널을 넘는다.** 1.35배, 머리·팔이 제목과 체력바 위로 겹친다 | 보스 칸 `overflow: visible`, 패널 위 겹(`z-index`) |
| 3형 | **화면 전체.** 1.8배, 싸움터가 전체 화면 무대로 바뀌고 가장자리에서 침범 연출이 자란다 | `position: fixed; inset: 0` 무대 겹(`100dvh`). 광장 칸·탭 위에 그림자 겹 |

- 침범 겹은 모두 `pointer-events: none`이다. 손을 막는 것은 **"가로막기" 장치 하나뿐**(덩굴이 단추 하나를 덮는다 → 문질러 걷어낸다)이고, 한 번에 하나, 나가기·탭 단추는 덮지 않는다.
- 3형 무대에는 늘 "광장으로" 단추가 있다. 무대를 나가도 싸움은 이어진다.
- `/r/<물결id>`(같이 잡자 링크)는 들어오자마자 이 무대를 연다.

### 2.5 변신 연출

형태가 바뀌는 순간(§3.2의 변신 커밋을 구독으로 받은 때) 모두의 화면에서 2초짜리 컷:
히트스톱 → 흰 번쩍임 → 실루엣이 부풀며 갑옷이 돋는다 → 충격파가 패널(3형은 화면)을 민다 →
이름 띠 "제2형 — 왕관 엉겅퀴" → 새 대사. 배경음이 형태마다 한 층씩 두꺼워진다(`feedback.ts`의 합성음).
그림 전환은 경로 모핑이 아니라 **겹 교차(크로스페이드 + 스케일)**로 한다. 늦게 들어온 사람은 컷 없이 그 형태로 시작한다.

막타도 같다 — 쓰러지는 커밋을 받으면 0.6초 느린 화면 뒤 겹이 차례로 무너진다.

## 3. 싸움 구조

### 3.1 지금과 달라지는 것

| | 2.0 | 3.0 |
|---|---|---|
| 형태 | 하나 | 셋까지. 빨리 잡으면 변신한다 |
| 게이지 | 체력 하나 | 체력 · 갑옷 · 울타리 |
| 내 몫 | 기력 60, 한 번 = 1(빈틈 2) | 기력 60 **형태마다 새로**, 내 역할의 일은 한 번 = 2, 남의 일은 1 (빈틈이면 다시 ×2) |
| 좋은 결과 | 30분 안에 잡기(★★★) | 3형까지 잡기(★★★) |
| 반격 | 기기마다 따로 | 시각에서 정해지는 대기술 — 모두 같은 순간 |

### 3.2 변신 — 빠를수록 세진다

```
1형 ──(세 게이지가 참)──┬─ 30분 안이면 → 2형으로 변신 ──┬─ 30분 안이면 → 3형 ── 처치 ★★★
                        └─ 넘었으면  → 처치 ★            └─ 넘었으면  → 처치 ★★
```

- 형태의 시작부터 30분(`RAID_FORM_FAST`) 안에 게이지를 채우면 **쓰러지지 않고 변신한다.** 넘겼으면 그 자리에서 쓰러진다.
  규칙이 둘 중 하나만 받으므로 화면이 고를 수 없다.
- **1형을 넘기면 상자는 확정이다.** 2·3형이 도망가도 상자를 받는다. 지금의 처치율 89%를 건드리지 않고 위쪽에만 굴곡을 더한다.
- ★은 넘긴 형태 수다(1–3). 뿌리 조각 1·2·3과 ★★★의 다년생 35%는 그대로 붙는다.
- 변신하면 모두의 기력이 60으로 돌아온다. 기력을 다 쓴 사람이 구경만 하던 문제가 여기서 풀린다.
- 도망 시각(태어나고 3시간)·폭주(마지막 30분)·빈틈(정각·30분부터 3분)·물결 일정은 그대로다.

**다음 형태의 크기는 온 사람 수에서 정한다.** 변신 커밋이 칸 여덟의 `fighters` 합을 읽어(쓰러뜨릴 때 이미 읽는 문서다)

```
다음 형태의 필요량 = max(종류 기본값, 72 × 참여 인원)   → 30 단위로 올림, 상한 60,000
```

72 = 한 사람이 제 역할로 빈틈 없이 넣는 120의 60%. 4명이면 기본값(540–900), 100명이면 7,200이다.
사람이 늘면 1형은 순식간에 넘어가는 서막이 되고, 2·3형이 그 인원에 맞는 본 싸움이 된다. 세울 때 인원을 알 수 없다는
문제를 변신이 푼다.

### 3.3 숫자와 불변식

| 것 | 값 | 까닭 |
|---|---|---|
| 기력 | 형태마다 60 | 지금 그대로 |
| 한 번의 값 | 내 역할의 게이지 2, 다른 게이지 1. 빈틈이면 ×2 | 한 사람이 한 형태에 넣는 최대 = 60 × 2 × 2 = **240** |
| 종류 기본 필요량 | 540 · 720 · 900 (지금 체력의 두 배) | 둘이 최대 480 < 540 — **혼자·둘이 못 잡는다** |
| 필요 인원 | 제 역할·빈틈 없이 5·6·8명, 빈틈까지 쓰면 3·3·4명 | 지금(5·6·8 / 3·3·4)과 같다. 제 역할을 안 하면 그 두 배 |
| 게이지 비율 (체력·갑옷·울타리) | 1형 70·30·0 / 2형 50·25·25 / 3형 40·30·30 | 1형은 쉬운 입문, 뒤로 갈수록 세 역할이 다 있어야 빠르다 |
| 한 커밋 | 기력 1–20, 값 80까지 | 필살기 20 × 4 |

역할이 비어도 막히지는 않는다 — 남의 일을 절반 값으로 할 수 있다. 3명이 모인 새벽 물결도 1형은 잡을 수 있다.

### 3.4 역할

처음 칠 때 고르고, 형태가 바뀔 때 다시 고를 수 있다(형태 안에서는 못 바꾼다). 화면은 지금 역할별 인원과 모자란 게이지를 늘 보인다
("울타리지기가 없어요 — 울타리 12%").

| 역할 | 채우는 게이지 | 하는 일 (손맛) | 대표 지원 |
|---|---|---|---|
| 🌾 낫잡이 | 체력 | 지금의 문지르기·콤보·약점 | 🥁 응원 북 |
| 🔍 돋보기꾼 | 갑옷 | 갑옷 판에 뜨는 표적을 골라 두드린다. 가짜 표적이 섞인다 — "출처" 있는 것만 진짜. 판이 깨지면 모두에게 10초 "무력화"(문지르기 절반) | 🔦 손전등 |
| 🛡️ 울타리지기 | 울타리 | 대기술 예고에 맞춰 막기 단추를 박자에 누른다. 맞춘 만큼 기력이 울타리로 들어가고, 울타리가 찰수록 모두가 맞는 묶임이 짧아진다 | ☂️ 큰 우산 |

- 지원 셋은 누구나 걸 수 있되 대표 지원은 기다림이 20초(나머지 60초)다. 지금의 아이템(북채·우산살·건전지)은 남의 지원을 20초로 줄이는 것으로 남는다. 지원은 여전히 손맛에만 닿는다.
- 세 일 모두 끝에서는 같은 것 — **기력 한 번을 어느 게이지에 넣는 커밋** — 이다. 줄 세우기·다시 보내기(`useRaid`)를 그대로 쓴다.
- 역할별 순위는 없다. 쓰러뜨린 뒤 "함께한 사람들"에 이름과 역할 그림만 나란히 올린다.

### 3.5 대기술 — 모두 같은 순간

반격을 기기마다 굴리지 않고 **형태가 시작한 시각에서 셈한다**(`hash(물결id, 형태, 차례)`). 쓰는 것이 없어도 모두가 같은 때
같은 예고를 본다 — 빈틈과 같은 방식이다.

| 것 | 값 |
|---|---|
| 간격 | 형태별 45 · 35 · 25초 안팎(폭주 때 더 잦다) |
| 예고 | 3초. 보스가 팔을 들고 눈이 타고, 화면에 범위가 깔린다 |
| 울타리지기 | 박자 맞춰 막기 → 울타리 게이지 |
| 그 밖 | 피하기 단추. 놓치면 묶임(지금의 반격과 같다, 가죽 장갑·큰 우산 그대로) |
| 종류 장치 | 방패·덩굴·가짜 약점은 2형부터의 갑옷 판·가로막기로 옮긴다 |

기기 시계가 몇 초 어긋나면 예고도 그만큼 어긋난다. 결과에 닿지 않으므로 받아들인다.

## 4. 규칙과 자료

### 4.1 문서

```
plazaRaids/{날짜-물결}
  hp, spawnedAt, defeatedAt            지금 그대로 (hp = 1형 필요량 합계)
  form        1–3                      새로. 없으면 2.0 물결이다
  formAt      이 형태가 시작한 때
  need        {h, b, g}                이 형태의 세 필요량
  base        {h, b, g}                앞 형태들이 끝났을 때의 칸 합계(이 형태의 0점)
  ├ shards/{0–7}    hits · brk · grd · fighters · names · aid…     게이지 셋을 나눠 센다
  └ fighters/{uid}  hits · uses · role(1–3) · form · pool · lastAt · shard · aid…
```

### 4.2 규칙이 지키는 것

| 것 | `firestore.rules` |
|---|---|
| 한 커밋 | 기력 1–20. 값 = 기력 × (pool == role ? 2 : 1) × (빈틈 ? 2 : 1). 내 칸의 그 게이지 하나만 그만큼 오른다 |
| 기력 | 표식의 `form`이 물결의 `form`과 같으면 `uses` ≤ 60, 다르면 0부터 다시(`form`을 맞추고, 이때만 `role`을 바꿀 수 있다) |
| 변신 | 칸 8의 합 − `base`가 `need` 셋을 다 넘고, `form` < 3이고, `formAt`에서 30분 안 → `form + 1`, `formAt = request.time`, `base` = 지금 합계, `need` = §3.2의 식(칸의 `fighters` 합)과 §3.3의 비율 |
| 처치 | 같은 조건에서 `form` == 3이거나 30분을 넘겼을 때만 `defeatedAt` |
| 세우기 | `form: 1`, 필요량 합계 ∈ {540, 720, 900}, 비율 70·30·0 |
| 2.0 물결 | `form`이 없는 물결은 지금 규칙 그대로(배포하는 날 떠 있는 물결). 옛 화면의 타격(pool 없음)은 새 물결에서 체력 1:1로 받는다 |
| 지우는 것 | 물결 문서를 직접 올리던 길과 `shard` 없는 표식 갈래(11-07 이후 0건) |

- 한 방은 읽기가 늘지 않는다(물결·내 표식·내 칸). 칸 여덟을 다 읽는 것은 변신·처치 커밋뿐이고 지금도 그렇다.
- `rules.ts` ↔ `firestore.rules`의 짝은 지금처럼 `raid.test.ts`가 보고, 갈래마다 `pnpm check:raid-rules`(에뮬레이터)에 경우를 더한다.
  규칙 한 번의 식 수 한도(1,000)는 에뮬레이터에서 변신 커밋으로 확인한다 — 옛 갈래를 먼저 지워 자리를 낸다.
- 배포 순서는 2.0과 같다. **규칙 먼저, 화면은 그 뒤.**

## 6. 순서

| 단계 | 내용 | 규칙 변경 | 볼 것 |
|---|---|---|---|
| **0. 등장 알림** | §8 전부. 보스 작업과 서로 기대지 않는다 — 콘솔 준비(§8.4)가 되는 대로 먼저 낼 수 있다 | 표식 경로 막기 한 줄 | 켠 기기 수, 알림으로 들어온 참여 |
| **1. 보스의 몸** | 리그·여섯 종류 세 형태·세 단계 무대·컷·대기술 시각표. 형태는 우선 지금의 체력 단계(1형 100–60% · 2형 60–25% · 3형 25–0%)에서 셈해 그린다 | 없음 | 저가 폰 프레임, 처치율이 그대로인지 |
| **2. 변신과 역할** | 형태·게이지 셋·역할·기력 새로 채우기·★ 바꾸기·묶음 쓰기. 규칙 → 화면 순서로 배포 | 있음 | 변신 비율, 2·3형 처치율, 역할 분포, 1형 처치율(89% 유지) |
| **3. 보상과 규모** | 각성 박제·"제 몫", 폴링 전환, 통계 | 없음 | 물결당 읽기 수 |

1단계는 화면만 바꾸므로 먼저 내보내 반응을 본다. 2단계에서 1단계의 "체력에서 셈한 형태"를 문서의 `form`으로 갈아 끼운다
(`raid/forms.ts`의 함수 하나).

되돌리기: 1형 처치율이 70% 아래로 내려가면 종류 기본값을 낮춘다(하한 540 = 둘이 못 잡는 선). 변신한 물결의 2형 처치율이
30%를 밑돌면 `72 × 인원`의 72를 낮추거나 `RAID_FORM_FAST`를 줄여 변신을 드물게 한다.

> **구현하며 바꾼 것 (2026-11-15, 1단계 — 보스의 몸).**
> - **그림:** `raid/boss/`에 종류마다 한 파일, 형태 셋. 겹은 여섯(오라·뒤·몸·갑옷·머리·앞)이고 `BossRig`가 쌓는다. 부품(`parts.tsx`)은 함께 쓴다.
>   종류별 `next/dynamic`은 하지 않았다 — 여섯 종류를 다 합쳐도 작고, 박제 진열이 여럿을 한 번에 그린다.
> - **입자는 캔버스가 아니라 SVG 점**(`Motes`)이다. 형태마다 열 개 안쪽이라 캔버스를 둘 까닭이 없었다.
> - **형태는 남은 체력에서 셈한다**(`raid/forms.ts`의 `raidForm` — 60% 아래 2형, 25% 아래 3형). 서버에는 형태가 없다.
>   체력 막대의 눈금도 75·50·25%에서 변신하는 자리(60·25%)로 바꿨다. 종류별 성질(방패·덩굴·가짜 약점)과 햇살·단계 대사는 그대로다.
> - **커지기:** 몸이 1 → 1.35 → 1.8배(`FORM_SCALE`). 커진 몸은 손을 받지 않는다(문지르기는 칸만 받는다) — 아래 단추를 가로채지 않게.
> - **3형의 전체 화면 무대**는 싸움터 칸을 그대로 화면 전체로 편다(`.raid-arena.is-staged`). 따로 화면을 만들지 않았다. "↙ 광장으로"로 나가고
>   "⛶ 전체 화면 무대"로 돌아온다. 포자를 뽑으려면 나가야 한다. 가장자리 침범(`Invade`)은 종류마다 다르고 손을 막지 않는다.
> - **가로막기(덩굴이 단추를 덮는 장치)는 넣지 않았다.** 갑옷·역할과 함께 2단계에서 본다.
> - **변신 컷** 2.2초(`MorphCut`) — 보던 사람에게만. 소리 `morph`를 더했다. 막타의 느린 화면은 지금의 피날레(`RaidFinale`)가 3형 그림으로 맡는다.
> - **대기술:** 반격을 `nextSkillAt`의 시각표로 옮겼다(형태별 45·35·25초, 폭주 ×0.6). 예고는 1.6초 → 3초. 묶이는 시간·피하기·우산·장갑은 그대로다.
>   지금도 "문지르던 사람만" 맞는다 — 구경하는 사람에게는 뜨지 않는다.
> - **옛 그림은 지웠다.** 박제는 1형 그림을 유리 덮개 안에 작게 둔다(눈의 X 표시는 뺐다). 몸의 금·별(`StageMarks`)도 새 그림과 맞지 않아 뺐다.
>   링크 카드(`/api/raid-card`)의 그림은 그대로다.
> - **확인한 것:** 파이어베이스 없는 모드의 광장에서 1형 → 2형 → 3형 변신 컷, 전체 화면 무대와 나가기, 대기술 예고, 여섯 박제. 타입·린트·테스트.
>   **확인하지 못한 것:** 실제 저가 폰의 프레임, 여럿이 함께 칠 때의 모습(혼자 쓰는 광장에서만 봤다).

> **구현하며 바꾼 것 (2026-11-15, 2단계 — 변신과 역할).**
> - **문서:** 목표는 모두 **쌓인 값**으로 둔다. 물결 문서의 `hp`(체력 목표)·`brk`·`grd`와 이 형태의 0점 `base{h,b,g}`·필요량 `n`·종류 기본값 `size`·`form`·`formAt`.
>   `need{}`는 두지 않았다 — 목표 − 0점으로 셈한다. `hp`를 쌓인 체력 목표로 둔 덕에 링크 카드처럼 `hp − hits`만 보는 곳이 그대로 돈다.
> - **기력은 형태마다 0부터 다시 센다**(`uses ≤ 60 × 형태`가 아니다). 표식의 `form`이 물결의 형태와 다르면 그 커밋이 새 형태의 첫 커밋이다 — 안 쓴 기력은 넘어가지 않는다.
> - **변신 커밋은 트랜잭션이 아니다.** 칸은 싸우는 동안 초마다 바뀌어 트랜잭션이 끝없이 겨룬다. 한 번 읽고 그대로 쓰되, 규칙이 읽은 뒤 들어온 몫을 받아 준다 —
>   0점은 "앞 목표 ≤ base ≤ 지금 합계", 필요량은 인원을 10명까지 늦게 읽어도 통과. 형태는 딱 하나만 오르므로 두 사람이 겹쳐도 한 번만 변신한다.
> - **규칙의 한도 둘에 걸려 고쳤다.** 함수 하나의 변수는 열 개까지(`raidMove`에서 `raidCellMoved`를 뗐다), 요청 하나의 식은 1,000개까지(칸 여덟을 값마다 따로 더하던 것을
>   `raidTotals`가 한 번씩만 읽어 맵으로 돌려준다). 에뮬레이터가 둘 다 잡았다.
> - **옛 화면:** 2.0 화면(역할을 모른다)은 3.0 물결에서 체력에 1:1로 친다. **2.0 이전 화면(uses 없는 표식)과 물결 문서를 직접 올리던 길은 지웠다** —
>   칸을 통째로 써서 갑옷·울타리를 지우기 때문이다(칸의 게이지는 줄 수 없다). 11-07 이후 그 길로 들어온 물결은 0/36이었다.
> - **역할별 인원은 화면에 보이지 않는다.** 표식은 본인만 읽는다. 대신 세 게이지의 남은 양을 늘 보이고, 내 게이지가 다 차면 덜 찬 게이지로 저절로 돌린다(그때는 ×1).
>   역할 분포는 `garden:stats`가 표식에서 센다.
> - **손맛:** 돋보기꾼은 표적이 쉴 틈 없이 뜨고 진짜('출처') 하나가 곧 한 방, 가짜('카더라')는 0 — 가짜 비율 35%, 손전등이면 없다. 울타리지기는 박자 판(한 방의 간격 1.2초,
>   앞뒤 0.26초)을 맞추면 한 방, 어긋나면 문지르기 한 번 값. 둘 다 몸을 문질러도 느리게는 들어간다. 대기술을 막는 것과 울타리 게이지는 잇지 않았다(대기술은 25–45초에 한 번이라 기력 60을 못 쓴다).
> - **지원의 대표 지원·기다림 차등(§3.4)과 "제 몫" 보상, 각성 박제, 가로막기는 넣지 않았다.** 3단계로 미룬다. ★은 넘긴 형태 수이고 조각 1·2·3은 그대로다.
> - **확인한 것:** 에뮬레이터에서 규칙 68갈래(`pnpm check:raid-rules`)와 화면 함수 그대로의 한 바퀴 — 세우기·치기·지원·변신 두 번·처치(`pnpm check:raid-client`, 22건).
>   파이어베이스 없는 광장에서 역할 고르기 → 치기 → 변신(20명 몫 1,440) → 기력 다시 참 → 역할 바꾸기 → 박자 판. 타입·린트·테스트 200.
>   **확인하지 못한 것:** 운영 규칙에 올린 뒤의 동작(`pnpm check:rules`는 3.0 모양으로 고쳤지만 배포 전이라 돌리지 못했다), 여럿이 동시에 칠 때의 변신 커밋.

### 8.2 방식 — FCM 주제(topic) 하나

기기마다 토큰을 Firestore에 모으지 않는다. 알림을 켠 기기를 FCM 주제 `raid`에 넣고, 보스가 서면 그 주제로
**한 번** 보낸다. 누가 켰는지의 장부도, 보낼 때의 부채질(fan-out)도, 죽은 토큰 청소도 FCM이 맡는다.

```
켜기   화면: 알림 권한 → 서비스 워커 등록 → FCM 토큰 → POST /api/push/topic {token, on: true}
        서버: ID 토큰 확인 → 주제 raid에 넣는다
끄기   화면: POST /api/push/topic {token, on: false} → 토큰 지움
등장   세운 화면: spawnRaid 성공 → POST /api/raid-notify {id}
        서버: ① 물결 문서를 읽는다(있고, 태어난 지 10분 안, 안 쓰러짐)
              ② plazaRaids/{id}/push/sent 를 "없을 때만 만들기"로 만든다 — 먼저 만든 요청만 보낸다
              ③ 한국 시각 8–22시면 주제 raid로 보낸다
```

| 것 | 내용 |
|---|---|
| 한 물결 한 번 | ②의 표식이 지킨다. 규칙은 그 경로에 쓰기를 주지 않는다(서버 계정만). 누가 라우트를 두드려도 다시 가지 않는다 |
| 세운 화면이 닫혀도 | 태어난 지 10분 안의 물결을 본 화면은 기기당 한 번 `/api/raid-notify`를 부른다. 표식이 겹침을 막는다 |
| 하루 상한 | 물결이 하루 다섯이라 알림도 다섯까지. 규칙이 물결 일정을 지키므로 더 늘릴 수 없다 |
| 밤 | 22–8시에 선 물결은 보내지 않는다(캘린더 알림과 같은 선) |
| 글 | 정해 둔 글뿐: "잼통 광장 · {종류 이름}이 나타났어요 — 3시간 안에 같이 잡아요". 종류는 물결 id에서 셈한다. 사람 이름은 싣지 않는다 |
| 누르면 | `/r/<물결id>` — 전체 화면 무대로 바로 들어간다 |
| 서버 인증 | 새 의존성 없이 실행 계정의 토큰(메타데이터 서버)으로 FCM v1·주제 관리·Firestore REST를 부른다. 주제 관리 REST가 막히면 `firebase-admin`을 런타임 의존성으로 올린다 |
| 로컬·설정 없는 환경 | 라우트는 503, 화면은 단추를 감춘다(다른 기능과 같다) |

### 8.3 설정 화면

- **자리 둘.** 광장의 "다음 거대 잡초는 … 뒤부터" 줄 옆 `🔔 나타나면 알려 주기`, 그리고 정원 설정.
  쓰러뜨린 직후의 결과 화면에도 한 번 권한다(가장 받고 싶을 때다).
- **켜진 상태는 기기마다**다(토큰이 기기 것이다). 이 기기의 장부(localStorage)에 적고, 켜져 있으면 하루 한 번
  토큰을 다시 받아 달라졌을 때만 주제에 다시 넣는다.
- 권한을 묻기 전에 무엇이 오는지 먼저 말한다 — "하루 다섯 번까지, 낮에만, 보스가 나타날 때". 브라우저 권한 창은 그 다음이다.
- **못 받는 환경은 숨기지 않고 말한다.**

| 환경 | 처리 |
|---|---|
| 안드로이드 크롬·데스크톱 | 그대로 된다 |
| iOS 사파리 | 홈 화면에 추가한 뒤에만 된다(16.4+). 추가하는 법을 그림으로 보인다 |
| 카카오톡 등 앱 안 브라우저 | 푸시가 없다. "브라우저로 열기"를 권하고 캘린더 알림을 대신 보인다 |
| 권한을 거절한 기기 | 브라우저 설정에서 푸는 법을 적는다. 다시 묻지 않는다 |

- `firebase/messaging`은 켤 때만 읽는다(`import()`). 켜지 않은 사람의 묶음에 들어가지 않는다.

>   **확인하지 못한 것:** 권한 창을 사람이 눌러야 해서, 토큰 발급 → 주제 등록 → 실제 수신은 기기에서 봐야 한다.
