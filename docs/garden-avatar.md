# 잼통 정원 — 내 방의 꼬마 (미니미 자리)

> 상태: 1·2단계 구현(2026-11-15). 3단계의 돌아다니기만 구현했다 — §12 "점검에서 고친 것·구현하며 바꾼 것"을 먼저 본다. 바탕 문서는 `docs/garden-miniroom.md`(이하 "방 문서")와
> `docs/garden-game.md`(이하 "본문서")이고, 두 문서의 선(§1·§2)은 이 안에서도 그대로 지킨다.
> 방 문서 §2에서 "미니미 — 뒤로 미룬다(그림 비용이 크다)", §9에서 "4단계: 정원지기 캐릭터(미니미 자리)"로 남겨 둔 자리를 채운다.
> 수치는 모두 첫 실험값이다.

## 0. 한 줄 요약

> 내 방 바닥에 **나를 대신하는 2등신 도트 꼬마**가 선다. 얼굴·머리·옷을 고르고, 오늘의 기분에 따라 표정이 바뀌고,
> 의자에 두면 앉고 침대에 두면 잔다. 방 음악이 흐르면 박자에 맞춰 몸을 흔든다. 옷은 잼으로 사거나 거둬서 얻는다.

그림 비용을 감당하는 방법이 이 설계의 핵심이다 — **옷 한 벌 = 몸통 그림 한 장.** 팔·다리·자세는 코드가 그리고
옷 색만 물려받는다. 그래서 자세가 늘어도 옷 그림은 늘지 않는다(§4).

## 1. 무엇을 빌리고 무엇을 빌리지 않는가

싸이월드의 미니미에서 **구조**를 빌린다. 이름·그림·말투는 잼통 것으로 만든다(본문서 §1, 방 문서 §3.3).

| 싸이월드 미니미 | 잼통의 꼬마 | 다르게 하는 점 |
|---|---|---|
| 2등신 도트 아바타 | 2등신 도트 꼬마, 20×24 도트 | 그림은 모두 새로. 실제 인물을 닮게 그리지 않는다(§9) |
| 얼굴형·헤어·의상을 도토리로 산다 | 기본 한 벌과 피부색·머리색은 **무료**, 나머지 옷은 잼·뿌리 조각·칭호로 | 현금으로 사지 못한다. 뽑기 없음. 기간제 없음 |
| 미니룸 안 특정 위치에 서 있음 | 바닥 칸 하나에 선다. 칸을 차지하지 않는다 | 가구 위에 세우면 그 가구에 맞는 자세(앉기·자기·연주) |
| 움직이기·음악에 맞춘 모션 | 숨쉬기·눈깜빡임, 돌아다니기(고를 수 있음), 방 음악 박자에 흔들기 | 움직임 줄이기 설정이면 멈춘 그림 |
| 말풍선 아이템 | 누르면 오늘의 기분 말풍선. 말풍선 틀은 상점 꾸밈 | 꼬마가 자유 글을 말하지 않는다(§9) |
| 고화질 리마스터 | **처음부터 해상도 무관** — 도트를 SVG 사각형으로 그려 어느 화면에서도 또렷하다 | 따로 리마스터할 일이 없다 |
| 3D·자이로·메타버스 | **하지 않는다** | 정면 방(방 문서 §4.1)과 맞지 않고, 지금 규모(하루 정원지기 중앙값 9명)에 필요 없다 |
| "미니미" | **"꼬마"**(가칭, §11의 1) | 방 문서 §10의 5 — 싸이월드 고유 이름은 쓰지 않는다 |

## 3. 생김새

### 3.1 몸

```
 20×24 도트, 1도트 = 2px → 40×48px (칸 너비 40, 맨 위 두 줄은 모자·머리카락 자리)

 열 0         15
   ┌──────────────┐  줄 0
   │  머리카락    │      ┐
   │ ┌──────────┐ │      │ 머리 11줄, 너비 14
   │ │ 눈·볼·입 │ │      │ (머리카락 뒤 · 얼굴 · 머리카락 앞 · 모자)
   │ └──────────┘ │      ┘
   ├───┬──────┬───┤  줄 11
   │ 팔│ 윗옷 │팔 │      ┐ 몸 11줄, 너비 10 (+팔)
   │   ├──────┤   │      │ 윗옷 6줄 · 아랫옷 3줄
   │   │아랫옷│   │      │
   │   │ 다리 │   │      │ 다리 1줄 · 신발 1줄
   └───┴──────┴───┘  줄 21┘
```

- **2등신**: 머리 11줄(y2–12), 몸 11줄(y13–23). 머리가 몸보다 넓다(14 대 10). 판이 머리보다 넓어서(20) 긴 머리·땋은 머리가 머리 옆으로 보인다.
- **정면만** 그린다. 방이 정면이다(방 문서 §4.1). 옆으로 걸을 때는 같은 그림을 좌우로 뒤집고 통통 튄다.
- 몸은 **하나**다. 체형·성별을 고르는 칸이 없다. 모든 옷과 머리는 누구나 입는다.
- 외곽선은 방 그림과 같은 먹색. 한 도트 = `<rect>` 하나지만, 같은 색이 이어지는 가로 줄은 하나로 합쳐 그린다
  (공유 카드의 `ImageResponse`가 사각형 수백 개에 느려지지 않게. 재 보니 꼬마 하나 107–149개(중앙값 122) — 시험은 170 아래를 본다).

### 3.2 부위와 겹치는 순서

뒤에서 앞으로:

| # | 부위 | 그림 | 고르는 것 |
|---|---|---|---|
| 1 | 머리카락 뒤 | 부위 그림 | 머리 모양에 딸림 |
| 2 | 몸(피부) | **코드**: 얼굴형 + 자세별 팔·다리 | 피부색 |
| 3 | 아랫옷 | 부위 그림(서 있는 모양) + 다리 색 | 아랫옷 |
| 4 | 윗옷 | 부위 그림(몸통만) + 소매 색 | 윗옷 |
| 5 | 신발 | **코드**: 발 두 도트에 신발 색 | 신발 |
| 6 | 얼굴 | 눈·입 그림. 기분이 바꾼다(§5.2) | 눈 모양 |
| 7 | 머리카락 앞 | 부위 그림 | 머리 모양, 머리색 |
| 8 | 모자 | 부위 그림. 쓰면 머리카락 앞의 윗부분을 가린다(그림마다 가림 줄 수) | 모자 |
| 9 | 얼굴 소품 | 안경·반창고·볼 스티커 | 소품 |
| 10 | 손에 든 것 | 부위 그림. 자세마다 손 위치(닻)가 다르다 | 든 것 |

### 3.3 색 — 칸에 이름을 붙이고 사람이 고른다

부위 그림은 색을 직접 적지 않고 **색 칸 글자**를 적는다. 그리는 쪽이 고른 색으로 바꾼다.

| 글자 | 칸 | 어디서 오나 |
|---|---|---|
| `.` | 투명 | — |
| `o` | 외곽선 | 먹색 고정 |
| `s` `S` | 피부·피부 그늘 | 피부색 고르기(무료, 8가지 — 사람 피부 6 + 하늘·연두 2) |
| `h` `H` | 머리·머리 그늘 | 머리색 고르기(무료, 10가지) |
| `a` `A` | 옷 바탕·그늘 | 그 옷의 표(옷마다 정해 둔 색, 또는 색 고르기가 되는 옷) |
| `b` `B` | 옷 둘째 색 | 그 옷의 표 |
| `k` `w` `p` | 눈 검정·흰색·볼 분홍 | 고정 |

- 피부색과 머리색은 **돈을 받지 않는다.** 바꾸는 데 잼이 들면 피부색이 "비싼 것과 싼 것"이 된다.
- 머리 모양 12 × 머리색 10 = 120가지가 그림 12장에서 나온다. 옷도 "색 고르기가 되는 옷"은 그림 한 장이 여러 벌이다.

## 4. 자세와 움직임 — 옷 그림을 늘리지 않고

### 4.1 자세

| 자세 | 언제 | 몸 그림(코드) | 위로 튀는 정도 |
|---|---|---|---|
| `stand` 서기 | 기본 | 팔 내림, 다리 모음 | 0 |
| `blink` | 서기 중 3–6초마다 한 번 | 눈만 감김 | 0 |
| `walk` 걷기 | 돌아다니기 | 서기 그림 그대로 | CSS로 1도트 오르내림 |
| `wave` 손 흔들기 ×2 | 누르면, 손님이 들어올 때 | 한 팔 올림 2장 | 0 |
| `hop` 뛰기 | 기분이 신남·두근두근일 때 누르면 | 팔 벌림 | 4도트 |
| `sit` 앉기 | 의자·소파·방석·벤치·흔들의자 칸 | 다리 접힘, 아래로 6도트 | −6 |
| `sleep` 자기 | 침대 칸, 기분이 졸려 | 눈 감김, 누운 대신 고개 숙임 + `z` | −8 |
| `play` 연주 | 피아노·키보드 칸 | 두 팔 앞으로 | 0 |
| `dance` 흔들기 | 방 음악이 흐를 때(합성곡) — **3단계, 아직 없음** | 팔 위·아래 번갈아 | 박자마다 2도트 |

- **팔과 다리는 코드가 자세마다 그린다.** 팔은 소매(윗옷의 `a`)와 손(피부), 다리는 아랫옷의 `b`와 신발 색.
  윗옷 부위 그림은 몸통만 담고, 아랫옷은 허리 아래 세 줄만 담는다. 그래서 **자세 9개 × 옷 n벌 = 옷 그림 n장**이다.
- 앉기·자기는 가구 그림에 맞춰 몸을 아래로 내린다(위 "튀는 정도"). 가구표에 `seat`(앉는 가구)·`bed`·`play`를 적는다.
- 머리는 자세와 따로 1도트 위아래로만 흔든다. 머리카락·모자·안경이 머리를 따라간다.

### 4.2 움직이는 방법 — 그리기를 다시 하지 않는다

| 움직임 | 방법 |
|---|---|
| 눈 깜빡임 | 감은 눈과 **다른 칸만**(사각형 열 개 아래) 겹쳐 두고 CSS `steps()`로 잠깐 보인다. 그 겹친 장에는 `opacity="0"` 속성 — CSS가 없는 공유 카드 이미지·움직임 줄이기에서는 안 보인다 |
| 칸 옮기기(돌아다니기) | 방 화면에서는 꼬마 `<g>`의 **CSS** `transform`(style)을 바꾸고 `transition`으로 미끄러진다(한 칸 0.8초). 공유 카드는 속성 `transform` — SVG 이미지로 그릴 때 style의 transform을 믿을 수 없다 |
| 박자 흔들기 | 곡이 바뀔 때 `musicGrid()`의 8분음표 길이로 `animation-duration`과 `animation-delay`를 한 번 맞춘다. 매 박자 JS를 돌리지 않는다 |
| 누름 반응 | 지금의 `garden-room-react-hop` 등과 같은 한 번짜리 CSS |
| 움직임 줄이기 | 모두 끈다. 서기 한 장. 누르면 말풍선만 뜬다 |
| 화면이 숨겨짐 | 돌아다니기 타이머를 멈춘다(CSS는 브라우저가 멈춘다) |

### 4.3 돌아다니기

- 주인이 고른다: **제자리 / 돌아다니기**(기본 제자리). 제자리면 정해 둔 칸에 선다.
- 돌아다니면 같은 줄의 옆 칸으로 한 칸씩 옮긴다. **가구 앞도 지나간다** — 꼬마는 자기 줄 가구 앞에 그려진다.
  멈춘 칸의 가구가 자세를 정한다(의자면 앉고, 침대면 잠깐 잔다).
- 5초마다 옆 칸 하나로. 갈 곳은 `rng(hash(방 이름 + 5초 번호))`로 정한다. 같은 때 방을 보는 사람은 같은 곳에서 본다(재미일 뿐, 맞추려고 서버를 쓰지 않는다).
- 꼬마는 칸을 **차지하지 않는다.** 가구 놓기(`canPlace`)가 꼬마 때문에 막히는 일이 없다.
  꼬마가 선 칸에 가구를 놓아도 옮기지 않는다 — 자세가 있는 가구면 그 자세, 아니면 가구 앞에 선다.
- 그리는 순서: 꼬마는 자기 줄(`b` 또는 `f`)의 가구 바로 앞에 그린다. `b`줄 꼬마는 `f`줄 가구에 가려질 수 있다 — 그게 깊이다.

## 5. 방에서 하는 일

### 5.1 누르기

| 누구 | 누르면 |
|---|---|
| 주인 | 꼬마가 손을 흔들고 기분 말풍선. 말풍선 옆 `👕 옷 갈아입기`·`😊 기분 바꾸기` 단추 |
| 손님 | 꼬마가 손을 흔들고 기분 말풍선 + 방 한마디(있으면). 말풍선 아래 `📮 방명록` |
| 꾸미기 중 | 움직이지 않는 그림일 뿐이다. 서는 자리는 옷 갈아입기 시트의 "서는 자리" 칸 표에서 고른다(**끌지 않는다**) |

- 방 한마디(`room.motto`)는 이미 그 방 안에서 보이는 글이고, 걸러서 받는다(방 문서 §4.6). 꼬마가 말풍선으로 한 번 더 보일 뿐
  새로 보이는 곳이 생기지 않는다. 공유 카드·미리보기에는 여전히 싣지 않는다.
- 꼬마의 누름 자리가 그 칸의 가구를 덮는다. 그래서 꼬마를 누르면 아래 단추 줄에 "〈가구〉 보기"를 함께 둔다(누를 수 있는 가구일 때).
- 말풍선은 4초 뒤 사라지고, 아래 단추 줄은 닫을 때까지 남는다.
- 손님이 방에 들어오면 손을 흔드는 것은 3단계(아직 없음).

| 바빠 🏃 | 고른 눈 | 동그라미 | — |
| 졸려 😴 | 감김 | 작은 o | `z` |
| 배고파 🍙 | 고른 눈 | 벌림 | — |
| 촉촉 🌧 | 고른 눈 | 처진 입 | — |
| 쉬는 중 🫖 | 감김 | 미소 | — |

- 가슴 별·책·우산 같은 기분 덧붙임은 뺐다(그림 비용 대비 작다). 침대 칸에 서면 기분과 상관없이 잔다.
- 눈 모양(콩·동그란·속눈썹·길쭉) 넷은 "고른 눈"일 때만 쓰인다. 감김·웃는 눈·반짝은 모든 눈 모양이 같이 쓴다 — 눈 그림이 넷 × 넷으로 늘지 않는다.

### 5.3 가구와 함께

- 가구표(`room/catalog.ts`의 `Furniture`)에 `pose?: "sit" | "sleep" | "play"`를 더한다.
  처음 붙일 것: 의자·소파·방석·흔들의자·광장 벤치(`sit`), 침대·방 안 텐트(`sleep`), 피아노·키보드(`play`).
- 피아노·키보드를 누르면 그 칸에 꼬마가 있을 때 `play` 자세로 바뀐다. 소리는 지금과 같다.
- 효과는 없다. 꼬마도 가구와 같이 **꾸밈일 뿐** 성장·싸움에 닿지 않는다(방 문서 §4.2).

### 5.4 방 음악과 흔들기

- 합성곡(`isGardenTrack`)이 흐르면 `dance`, 박자는 `musicGrid()`의 8분음표 두 개마다 한 번.
- 녹음·스트리밍 곡에는 박자 정보가 없다. 박자를 지어내지 않고 고개만 천천히 끄덕인다(2초 주기) + 머리 위 음표.
- 음악이 꺼져 있으면 흔들지 않는다. 꼬마가 소리를 켜지 않는다.

## 6. 자료

### 6.1 장부 — `RoomData`에 더한다

```ts
// features/garden/avatar/rules.ts
export interface AvatarLook {
  skin: number;        // 피부색 번호 0–7
  hairColor: number;   // 머리색 번호 0–9
  hair: string;        // 머리 모양 id
  eyes: string;        // 눈 모양 id
  top: string;         // 윗옷 id
  bottom: string;      // 아랫옷 id
  shoes: string;       // 신발 id
  hat?: string;
  face?: string;       // 얼굴 소품
  held?: string;       // 손에 든 것
  tint?: Partial<Record<"top" | "bottom" | "hat", number>>; // 색 고르기가 되는 옷의 색 번호
  bubble?: string;     // 말풍선 틀 id
}

export interface AvatarData {
  on: boolean;          // 방에 세우기. 끄면 방에 없다(장부는 남는다)
  at: string;           // 바닥 칸 "b2" | "f4"
  roam: boolean;        // 돌아다니기
  look: AvatarLook;
  owned: string[];      // 산·받은 옷 id. 처음부터 가진 것은 적지 않는다
}

// room/rules.ts의 RoomData
avatar?: AvatarData;    // 옛 장부에는 없다 → normalizeAvatar가 채운다
```

- 옷장의 "가진 것"은 가구의 `owned`(수를 센다)와 따로 둔다. 옷은 하나면 충분하고, 가구 `OWN_MAX` 같은 수가 없다.
- 새 정원: 만들 때 무작위 seed로 기본 꼬마를 정해 **장부에 저장**한다(무료 부위 안에서). 기기를 바꿔도 같은 꼬마다.
- 옛 장부: 공개 id가 없는 정원도 있어서 seed는 **정원 이름**이다(`normalizeRoom(raw, nick)`). 저장되기 전에 다시 열어도 같은 꼬마.
- 표에 없는 id(옷이 빠졌거나 손으로 고친 장부)는 그 부위의 기본으로 바꾼다. 가지지 않은 옷을 입은 장부는 **공개할 때** 그 부위를 기본으로 바꾼다(`ownedLook`) — 장부를 손으로 고친 반칙은 혼자의 문제고, 공개 방에는 퍼지지 않는다.
- 받는 옷은 옷 갈아입기 시트를 열 때 조건(칭호·황금 도감·박제 수)을 보고 `owned`에 넣는다(`claimWear`). 그 뒤로는 산 옷과 같다.

### 6.2 공개 문서 — 문자열 하나

`gardens/{gid}.room.avatar`에 **꼬마를 압축한 문자열 하나**를 싣는다. 꼬마를 세우지 않았으면 키가 없다.

```
1;f2;1;3;7;bob;round;tee.4;pants.2;sneaker.1;straw;glasses;can;cloud
│ │  │ │ │ └ 머리;눈;윗옷[.색];아랫옷[.색];신발[.색];모자;얼굴 소품;든 것;말풍선 — 열네 칸, 없는 것은 빈 칸
│ │  │ │ └ 머리색 0–9
│ │  │ └ 피부색 0–7
│ │  └ 돌아다니기 0|1
│ └ 칸(b·f 0–9)
└ 판(모양이 바뀌면 2)
```

- 글이 들어갈 자리가 없다. id는 `[a-z0-9-]` 12자까지, 색은 숫자만. 색 고르기가 없는 옷에는 색 번호를 싣지 않는다.
- 보는 쪽(`avatarFromPublic`)이 판·칸·id를 다시 보고, 모르는 것은 그 부위의 기본으로 그린다(키보드의 `keysFromPublic`과 같다).
- **가졌는지는 공개 문서가 말하지 않는다.** 산 옷인지 아닌지는 개인 장부의 일이다(본문서 §3.12). 공개 문서에서 보는 것은 "표에 있는 id인가"뿐이다.

`firestore.rules`의 `publicRoom()`:

```
r.keys().hasOnly([..., 'avatar'])
&& (!('avatar' in r) || (r.avatar is string && r.avatar.size() <= 160
      && r.avatar.matches('^1;[bf][0-9];[01];[0-9];[0-9];[a-z0-9.;-]{0,140}$')))
```

- 문자열 하나라서 규칙의 계산 한도(키보드가 이미 많이 쓴다, 방 문서 "키보드 여러 개의 저장")를 거의 쓰지 않는다.
- 160자는 부위 10개 × id 12자 안팎에 넉넉하다. 실제 길이와 정규식이 규칙과 같은지는 `avatar/avatar.test.ts`가 가장 긴 조합으로 본다.

### 6.3 표 — `avatar/catalog.ts`

```ts
export type Part = "hair" | "eyes" | "top" | "bottom" | "shoes" | "hat" | "face" | "held" | "bubble";

export interface Wear {
  id: string;            // [a-z0-9-], 12자까지
  part: Part;
  label: string;
  price: number;         // 0이면 처음부터
  cur?: "root" | "reward";
  reward?: RewardRule;   // cur가 reward일 때 — 어떻게 받는가(§7.2)
  tint?: boolean;        // 색 고르기가 되는 옷
  art: Sprite;           // 색 칸 글자로 쓴 도트 줄들
  hide?: number;         // 모자: 머리카락 앞의 위 몇 줄을 가리나
  hint: string;
  newUntil?: string;
}

/** 도트 그림. 줄마다 같은 길이, 글자는 §3.3의 색 칸. back은 머리카락 뒤처럼 몸 뒤에 그릴 것. */
export interface Sprite { rows: string[]; dx: number; dy: number; back?: string[] }
```

- 그림은 모두 이 파일(또는 부위별 파일)에 코드로. 그림 파일·외부 이미지가 없다. 빌드에 그대로 들어간다(옷 60벌 × 평균 300자 ≈ 18KB, 압축 전).

### 7.1 무료로 시작하는 것

  가구와 같이 잼 분포(`garden:stats`)를 보고 다시 맞춘다.
- 뽑기 없음. 기간제 없음. 사용자 사이에 옷을 주고받지 않는다(본문서 §1).

| **1. 꼬마 세우기** | `avatar/` 표·규칙·그리기, 무료 부위 전부, 기분 → 표정, 누르기·말풍선, 앉기·자기·연주, 칸 고르기, 공개 문자열·규칙, 옷 갈아입기 화면, 기본 꼬마 | 꼬마를 세운 방 수, 꼬마 누름(`avatar_tap{mine}`) |
| **2. 옷장 상점** | 👕 칩, 잼 옷 30여 벌, 입어 보기, 받는 옷(칭호·황금·박제), 전리품 옷, 말풍선 틀, 홈 프로필 띠 | 옷장에서 잼을 쓴 정원 수, 잼 분포의 꼬리 |
| **3. 움직임·사람 사이** | 돌아다니기, 박자 흔들기, 손님 맞이 손 흔들기, 방명록·1촌 목록의 얼굴, 싸움터 얼굴 줄 | 1촌 방 방문 중 꼬마 누름 비율 |

1단계에서 옷장 상점을 빼는 까닭: 꼬마가 방에 서서 표정이 바뀌는 것만으로 "내 방에 내가 산다"가 된다. 팔 것은 그 뒤에 얹는다.
그림 시험(0단계)을 먼저 하는 까닭: 크기가 틀리면 모든 부위 그림을 다시 그린다. 그림 비용이 이 기능의 거의 전부다.

### 10.1 코드 자리

```
src/features/garden/avatar/
  palette.ts      피부·머리·옷 색, 고정 색 글자
  sprites.ts      판 크기, 자세별 몸 그림, 머리, 눈·입 좌표, z
  catalog.ts      옷장 표(Wear) — 머리·옷·모자 그림이 여기 있다. AVATAR_NAME(가칭 "꼬마")
  compose.ts      부위 겹치기(§3.2 순서) → 색 격자 → 가로 줄 합친 사각형. 깜빡임용 다른 칸만
  rules.ts        normalizeAvatar, packAvatar/avatarFromPublic, ownedLook, 기분 → 표정, 가구 → 자세,
                  돌아다니기 다음 칸, buyWear, grantRewards. room/rules.ts를 import하지 않는다(순환)
  AvatarArt.tsx   AvatarFigure(방·카드), AvatarIcon(시트·상점)
  Wardrobe.tsx    옷 갈아입기 시트
  avatar.test.ts
src/features/garden/shop/WearShop.tsx   상점 👕 옷장
```

- `compose.ts`는 DOM이 없는 순수 함수라 `ImageResponse`에서도 그대로 쓴다.
- `RoomSvg`가 꼬마를 자기 줄의 마지막 가구 바로 뒤에 그린다(`AvatarInRoom`). 누르기·말풍선·돌아다니기는 `RoomScene`(RoomArt.tsx).
- 가구표에 `pose`를 더했다: 의자·소파·방석·흔들의자·광장 벤치 `sit`, 침대·방 안 텐트 `sleep`, 피아노·키보드 `play`.

### 10.2 시험

| 시험 | 본다 |
|---|---|
| 표 | 모든 부위 그림의 줄 길이가 같고, 색 칸 글자가 §3.3 안에 있고, 판(20×24) 밖으로 나가지 않는다 |
| 자세 × 부위 | 모든 자세 × 모든 옷이 그려진다. 사각형 170 아래, 깜빡임 장 10 아래, 발이 판 맨 아래 줄에 닿는다 |
| 압축 | `packAvatar` → `avatarFromPublic`이 되돌아온다. 가장 긴 조합이 160자 아래이고 규칙의 정규식에 맞는다 |
| 거르기 | 표에 없는 id·이상한 칸·판 → 기본. 가지지 않은 옷을 입은 장부 → 공개 문자열에서 그 부위가 기본 |
| 가구 | 그 칸(2칸 가구의 오른쪽 칸 포함)의 가구가 자세를 정한다. 돌아다니기는 같은 줄의 빈 칸·자세 가구 칸으로 한 칸씩 |
| 규칙 | `pnpm check:ilchon-rules`(에뮬레이터)에 꼬마 일곱 갈래(통과 1, 한글·대문자·판·벽 칸·161자·문자열 아님 거절)를 더했다 |

### 10.3 배포 메모

**순서: Firestore 규칙 → 화면.** 새 화면은 공개 방에 `room.avatar`를 싣는다. 지금 배포된 `publicRoom()`은 이 키를 받지 않으므로(`hasOnly`)
화면이 먼저 나가면 **꼬마를 세운 모든 사람의 공개가 거절된다**(방 문서 §8의 2와 같은 모양). 새 규칙은 옛 화면의 모양(키 없음)을 그대로 받는다.
Storage는 쓰지 않는다(그림이 코드에 있다). 색인은 새로 없다.

### 10.4 계측

`avatar_edit{parts}`(저장할 때 바뀐 부위 이름만 쉼표로 — 고른 id·색은 보내지 않는다), `avatar_tap{mine}`, `avatar_place{on, roam}`,
`shop_buy{cat: "wear"}`. 새 이벤트라 GA 쪽 설정은 없어도 된다.
