## 0. 한 줄 요약

**하루 3~5분, 잼통이와 한 판씩 풀면서 업적·정책·언행의 근거를 익히고, 익힌 근거는 "근거노트"에 모여 논쟁할 때 바로 꺼내 쓴다.**
듀오링고의 리듬(짧은 한 판, 매일 이어 가기, 단계가 열리는 길, 잊을 때쯤 다시 묻기)은 빌린다.
경쟁(리그·순위·친구와 점수 비교)은 들이지 않는다. 그림·애니메이션은 Codex CLI로 GPT에게 만들게 한다.

## 1. 왜 만드는가 — 목적과 성공의 모습

이 기능의 목적은 하나다. **지지자가 지인과 이야기할 때 자신 있게, 근거를 들어 말하게 한다.**
(목표 독자: 지지자가 지인에게 근거로 보내는 것이 1순위, 객관성이 가장 앞선다.)

그래서 "많이 외웠다"보다 다음 넷을 할 수 있게 되는 것이 성공이다.

| 할 수 있게 되는 것 | 예 |
|---|---|
| ① 무엇을 한 정책인지 한두 문장으로 말한다 | "대장동은 공공이 의결권 과반을 쥔 민관합동 개발이었다" |
| ② 그것이 **확인된 사실인지, 누구의 주장인지** 가린다 | "그건 경기도가 밝힌 효과고, 독립 검증은 아직이야" |
| ③ **어디에 적혀 있는지** 댄다 | 1차 자료(관보·보도자료·판결문)와 기사를 구분해서 링크를 보낸다 |
| ④ **반론과 한계도** 안다 | 상대가 비판을 꺼내면 "그 지적은 맞고, 다만 …"으로 받는다 |

④가 빠지면 논쟁에서 진다. 상대의 반론을 처음 듣는 순간 말문이 막히기 때문이다.
그래서 반론·한계는 "틀린 것"이 아니라 **함께 알아야 할 지식**으로 가르친다(`garden-game.md` §1 "반론을 잡초로 그리지 않는다"와 같은 선).

## 2. 지키는 선

`garden-game.md` §1의 선을 모두 지킨다. 여기에 공부 기능만의 선을 더한다.

| 원칙 | 이유 |
|---|---|
| **경쟁 없음** — 리그, 순위표, 친구와 점수·연속일 비교, "○○님이 앞질렀어요" 알림을 만들지 않는다 | 목적은 이해다. 경쟁은 빨리 찍기를 보상하고, 정치 콘텐츠에서는 "누가 더 열성인가" 집계가 된다 |
| 목숨(하트)·틀리면 막히는 장치 없음 | 틀리는 순간이 가장 잘 배우는 순간이다. 막으면 틀리는 것을 피하려고 덜 푼다 |
| 연속일은 **부드럽게** — 쉼표가 기본으로 있고, 끊겨도 꾸짖지 않는다 | 죄책감으로 붙잡는 리듬은 오래가지 않고, 이 사이트의 말투와 맞지 않는다 |
| **모든 문항은 claim으로 참·거짓이 가려진다** — 문항마다 `claimIds`를 달고, 풀이는 그 claim으로 답한다 | 위키의 앵커 규칙과 같다. 근거 없는 문항은 쓰지 않는다 |
| `CLAIM`은 주장한 사람을 문장에 넣는다. `verified: false` claim은 정답의 근거로 쓰지 않는다 | `quizzes/ox.ts`의 규칙을 그대로 잇는다 |
| `validUntil`이 지난 claim, 소스가 아닌 것(`cheers`, Firestore 응원·제보)은 쓰지 않는다 | AGENTS.md "raw source가 아닌 것" |
| X 문항(흔한 오해)은 문제 화면에서만 보이고 곧바로 풀이가 붙는다. 근거노트·공유에 싣지 않는다 | 오해 문장이 따로 떠돌지 않게 |
| 공유 횟수에 보상 없음. 공유 링크는 언제나 원본 페이지(canonical) | `garden-game.md` §1 |
| 정치 성향을 추론할 수 있는 집계 없음. 문항별 정답률은 **문항 품질** 점검에만 쓴다 | `analytics.ts` 원칙 |
| 듀오링고의 이름·캐릭터·그림·소리를 쓰지 않는다 | 메커니즘만 빌린다. 마스코트는 잼통이 |

## 4. 학습 모델

### 4.1 단위

```
길(코스)  ─  단원  ─  레슨  ─  문항
```

- **길**: 주제 묶음. 처음에는 넷 — `업적의 길`, `정책 팩트의 길`, `말과 연설의 길`, `카르텔의 길`.
  분야(`categories`)별 작은 길(부동산·복지·외교…)은 2차.
- **단원**: 업적 하나, 정책 하나, 언행 한 편, 카르텔 하나. 원본 페이지 하나와 1:1이다(원본 링크가 늘 있다).
- **레슨**: 단원 안의 다섯 단계. 앞 단계를 마쳐야 다음이 열린다.

| 단계 | 이름 | 익히는 것(§1의 ①~④) | 주 문항 |
|---|---|---|---|
| 1 | 🌱 **알기** | ① 무엇을 한 정책인가 | 쉬운 설명 장면 보기 → O/X, 빈칸 |
| 2 | 🌿 **이해** | ① 누구 대상, 끝났나·계획인가, 숫자의 뜻 | 숫자 뜻, 순서 맞추기 |
| 3 | 🔍 **출처** | ② ③ 사실/주장, 어디에 적혀 있나 | 사실·주장 가리기, 출처 고르기 |
| 4 | ⚖️ **반론** | ④ 비판과 한계 | 반론도 알기 |
| 5 | 💬 **말하기** | ①~④를 묶어 답한다 | 대화 답장(§5.9) |

단원의 다섯 단계를 마치면 그 단원은 **열매**가 된다. 정원의 기념품이 한 단계 자란다(§7).

### 4.2 숙련도와 다시 묻기

- 문항마다 **라이트너 상자 5칸**을 둔다. 맞히면 한 칸 오르고, 틀리면 1칸으로 돌아간다.
  칸마다 다시 묻는 간격: 1일 · 3일 · 7일 · 16일 · 35일. (SM-2 같은 정교한 알고리즘은 쓰지 않는다 — 단순하고, 테스트하기 쉽고, 설명하기 쉽다.)
- 단원 숙련도 = 그 단원 문항의 상자 평균. 화면에는 씨앗 → 새싹 → 꽃 → 열매 그림으로만 보인다(숫자 점수 없음).
- 오래 안 본 단원은 꽃이 살짝 고개를 숙인다. 시들어 죽지는 않는다.
- 순수 함수로 둔다: `src/features/study/srs.ts` + `srs.test.ts`. 시각은 `rules.ts`의 `kstDay`로 KST 하루를 센다.

### 4.3 오늘의 한 판

한 판은 **8문항 안팎, 3~5분**이다.

1. 다시 물을 때가 된 문항(due)을 먼저, 많아야 5개.
2. 나머지는 지금 진행 중인 단원의 새 문항.
3. 같은 단원 문항이 연달아 셋 넘게 나오지 않게 섞는다. 단, 레슨 안에서는 한 단원만.
4. 판 끝에 그날 익힌 근거 카드가 펼쳐진다(§6.2 근거노트으로 들어간다).

하루 목표는 사용자가 고른다 — **가볍게(1판) · 꾸준히(2판) · 열심히(3판)**. 목표를 넘겨도 더 주는 것은 없다(자랑할 숫자를 만들지 않는다).

## 5. 문항 유형

모든 유형은 `claimIds`를 갖고, 풀이는 그 claim의 문장으로 답하며, 풀이 아래에 **"원문 보기"**(원본 페이지의 해당 claim 위치)와 **출처 링크**가 붙는다.

| # | 유형 | 화면 | 재료 | 단계 |
|---|---|---|---|---|
| 5.1 | **O/X** | 한 문장 → ⭕/❌ | `quizzes/ox.ts` 그대로 | 1 |
| 5.2 | **빈칸** | 핵심 낱말 하나를 보기 셋 중에서 | claim 문장, 언행 `easy.points` | 1 |
| 5.3 | **숫자 뜻** | "늘었다/줄었다", "어느 쪽이 크다". 숫자 자체를 맞히게 하지 않는다 | `keyNumbers` + claim | 2 |
| 5.4 | **순서 맞추기** | 사건 카드 3~4장을 끌어 놓기 | `timeline` | 2 |
| 5.5 | **사실·주장 가리기** | 문장을 보고 "확인된 사실 / ○○의 주장 / 해석"으로 | claim `assertionType`, `assertedBy` | 3 |
| 5.6 | **출처 고르기** | "이 사실은 어디에 적혀 있나?" 보기: 관보·보도자료·판결문·기사 | claim → `sources`의 `type` | 3 |
| 5.7 | **반론도 알기** | "이 정책에 제기된 비판으로 맞는 것은?" — 실제 반론 하나 + 다른 단원의 반론 | `counterpoints`, 정책 `critiqueIds`·`gaps` | 4 |
| 5.8 | **소문에 답하기** | SNS에서 도는 말 → 그 말에 답하는 근거 카드 고르기 | 정책 `rumors` + 대응 claim | 4·5 |
| 5.9 | **대화 답장** | 지인의 메시지 말풍선 → 근거 카드 2~3장을 골라 답장을 만든다 → 완성된 답장과 출처 링크를 보여 준다 | 단원의 claim·반론 전체 | 5 |

### 5.9 대화 답장 — 이 기능의 얼굴

듀오링고의 "말하기 연습"에 해당한다. 실제 쓰임(지인에게 근거 보내기)과 가장 가깝다.

```
 ┌─────────────────────────────┐
 │ 💬 친구                       │
 │ "대장동 그거 민간이 다 해먹은 거 │
 │  아니야?"                      │
 └─────────────────────────────┘
   어떤 카드로 답할까? (2장)
   [공공이 의결권 과반]  [확정이익 방식]
   [1심 배임 유죄]        [다른 업적 카드]
           ↓
 ┌─────────────────────────────┐
 │ 🫙 내 답장                     │
 │ 사업 회사는 성남도시개발공사가   │
 │ 의결권 과반을 갖는 구조였어.     │
 │ 다만 1심은 관련자 배임을 인정했고 │
 │ 항소심 진행 중이야. [출처 2]     │
 └─────────────────────────────┘
```

- 정답이 하나가 아니다. **반드시 들어가야 할 카드**(핵심 사실)와 **넣으면 더 좋은 카드**(한계·반론)를 문항이 정한다.
  핵심을 빠뜨리면 "이것도 넣어 보세요", 반론 카드를 넣으면 "상대가 먼저 꺼내기 전에 인정하면 더 믿음을 얻어요".
- 답장 문장은 **카드마다 미리 적어 둔 `say`를 이어 붙인 것**이다. `say`는 근거 claim 문장을 말투만 바꾼 것이고, 문항을 쓸 때 claim과 대조한다(§10.2). 화면에서 자유 작문을 생성하지 않는다(모델 호출 없음, 환각 없음).
- 상대 말에서 **맞는 부분을 먼저 인정하는 카드**를 "꼭 넣을 카드"로 자주 둔다(예: "IMF가 직접 낸 숫자가 아니다"). 객관성이 논쟁에서 가장 강한 무기라는 것을 문항이 가르친다.
- 완성된 답장은 "복사" 버튼으로 가져갈 수 있다. 복사하면 원본 페이지 링크가 함께 붙는다(canonical). 복사 횟수에 보상 없음.
- 친구 메시지는 **정책 `rumors`의 요약** 또는 업적 X 문항의 오해에서만 가져온다. 실존 인물·특정 계정을 흉내 내지 않는다.

## 6. 진행 관리 — 경쟁 없이 계속 오게

### 6.1 이어 가기(연속일)

- 하루 목표를 채우면 그날의 잼통이 도장이 찍힌다. 달력에 도장이 이어진다.
- **쉼표**: 주마다 2개가 저절로 채워진다. 빠진 날은 쉼표가 메운다. 잼으로 사지 않는다.
- 끊겨도 "괜찮아요, 오늘부터 다시"만 말한다. 끊긴 날수를 강조하지 않는다.
- 연속일은 본인만 본다. 1촌·방·공유 카드에 나가지 않는다.

### 6.2 근거노트 (근거노트 탭)

- 레슨에서 익힌 근거(O 문항의 claim, 출처, 반론)가 **카드**로 모인다. X 문항 문장은 넣지 않는다.
- 단원별·주제별로 찾고, 카드 하나를 누르면 claim 문장 + 출처 + 원본 링크 + "복사".
- **논쟁 직전에 꺼내 보는 곳**이 목표다. 그래서 공부 홈의 맨 위, 검색 가능하게.
- 카드는 원본 콘텐츠를 가리키는 앵커(`<slug>#<claimId>`, `policy:<slug>#<claimId>`)만 저장한다. 원본이 고쳐지면 카드도 따라 바뀐다.

### 6.3 나의 길 지도

- 길마다 단원이 이어진 오솔길 그림. 지나온 단원은 꽃·열매, 다음 단원은 반짝인다.
- 분야별 꽃밭(부동산·복지·외교…)이 얼마나 피었는지 한눈에. 숫자 점수·백분율은 보이지 않는다.

### 6.4 주간 돌아보기

- 일요일 저녁, 본인에게만: "이번 주에 익힌 근거 12장 · 새로 꽃 핀 단원 2곳 · 다시 볼 카드 5장".
- 비교 문구("상위 ○%")는 쓰지 않는다.

### 6.5 1촌과 함께 — 비교 없이

- 1촌의 방에 **"같이 공부해요" 응원 쪽지**를 남길 수 있다(방명록과 같은 길). 점수·연속일은 보이지 않는다.
- 다 익힌 단원의 기념품(§7)은 방에 놓이므로, 방을 구경하는 1촌이 자연히 본다. 이것이 전부다.

### 6.6 배지

- **알아낸 것**으로만 준다: "첫 반론을 익혔어요", "1차 자료 10장을 찾았어요", "정책의 길 한 바퀴".
- 연속일 배지는 7일·30일 두 개만, 조용히. 공유 횟수·정답률 배지는 없다.

## 7. 정원과 잇기

공부는 정원과 **따로 들어올 수 있지만**, 보상은 정원으로 간다. 정원의 76%가 첫 수확 전에 떠나는 입구 문제(`garden-achievement-strategy.md` §1)에 공부가 두 번째 문이 된다.

| 공부에서 | 정원에서 |
|---|---|
| 하루 목표 채움 | 🍯 소량 + 물뿌리개 한 번(텃밭 하나를 조금 빨리). 하루 상한이 있다 — 공부가 잼 채굴이 되지 않게 |

## 8. 잼공 앱 구성

정원(`/garden`)처럼 **사이트 안의 별도 앱**이다. 자기 상단 바, 자기 하단 탭 다섯, 탭마다 칸(segment)을 갖는다.
정원의 `nav.ts`(탭·칸·옛 이름 받기, 순수 함수 + 테스트) 구조를 그대로 본뜬다 → `src/features/study/nav.ts`.

### 8.1 사이트 하단 탭 바꾸기

| | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 지금 | 홈 | 위키 | 업적 | 언행 | 정원 |
| 바뀐 뒤 | 홈 | **잼공** | 업적 | 언행 | 정원 |

- `src/features/app/BottomNav.tsx`의 `TABS`에서 위키를 `{ href: "/study", label: "잼공" }`으로 바꾼다.
- **위키는 없어지지 않는다.** `/wiki` 주소는 그대로다. 들어가는 길을 셋으로 둔다.
  1. 업적 탭이 위키를 자기 것으로 친다(`owns: ["/achievement", "/cartel", "/wiki"]`). 정부 정책 팩트·카르텔이 위키에 있어 업적 탭과 한 묶음이다. 업적 목록(`/explore`) 위에 「업적 · 정부 정책·위키 · 카르텔」 칸을 둔다.
  2. 상단 메뉴(`AppMenu.tsx`)에 「위키 · AI에게 묻기」.
  3. 잼공 교실의 「잼통이에게 묻기」가 위키 AI 질문(`AskWikiBox`, `/api/wiki-ask`)을 그대로 쓴다. AI 질문이 엄지 자리에서 사라지지 않는다.
- 위키 하단 탭을 쓰던 사람을 위해 교체 뒤 2주 동안 `/wiki` 위에 "위키는 업적 탭으로 옮겼어요" 띠를 둔다.

### 8.2 탭과 칸

- 첫 화면은 언제나 **교실 › 오늘**. 처음 온 사람은 첫 안내(하루 목표 → 첫 길 → 첫 레슨)부터.

- 상단 바: 「← 잼통」(사이트로) · 잼공 · 🫙 이어 간 날 · ⏸ 남은 쉼표. 잼(🍯)은 정원 것이라 여기 두지 않는다.

### 8.3 주소

- `/study` — 교실 › 오늘. 칸은 정원처럼 `?tab=<자리>`(`/study?tab=reply`). 자리 이름은 `nav.ts`에서 탭·칸으로 푼다.
- `/study/u/<길>/<단원>` — 단원 시트를 연 채로 연다(원본 페이지의 "이 내용으로 연습하기"가 여기로 온다).
- 잼공 화면은 모두 `noindex`. 검색엔진에는 원본 페이지만 나간다(클로킹 방지, `garden-game.md` §1).
- 정원과 같은 익명 계정(uid)·닉네임·잼통이를 쓴다. 상태 저장은 따로(§11).

### 8.4 다른 곳에서 들어오는 문

- 사이트 하단 탭 「잼공」. 오늘 목표를 아직 안 채웠으면 탭 아이콘에 작은 점.
- 홈: "오늘의 한 판" 카드(정원의 `GardenHomeCard`와 나란히).
- 업적·정책·언행 원본 페이지 아래: 작은 **"이 내용으로 연습하기"** 배지 하나. 원본을 가리지 않는다.
- 정원 방 › 기념관: "공부해서 키우기" 링크. 정원 › 잡초 O/X 퀴즈 풀이 아래: "이 단원 공부하기".

### 8.5 푸시 알림

정원에는 이미 FCM 웹 푸시가 있다(`src/lib/firebase/push.ts`, `public/push-sw.js`, `/api/push/topic`). 잼공은 그 길을 쓰되 **사람마다 다른 알림**이 필요해 구조가 하나 다르다.

**보내는 것**

| 종류 | 언제 | 글(잠금 화면에 내용 숨기기 켬 / 끔) |
|---|---|---|
| 공부 알림 | 사용자가 고른 시각(8·12·20·21시), **목표를 아직 안 채운 날만** | "🫙 잼통이가 기다려요 · 오늘의 한 판(약 4분)" / "대장동 반론 단계 · 다시 볼 카드 4장" |
| 이어 가기 지킴 | 위와 같은 알림에 합친다. 쉼표가 0개이고 오늘 안 하면 끊기는 날 | "오늘 하면 13일째예요" (꾸짖는 말 없음) |
| 새 단원·고쳐진 내 근거 | 그날 공부 알림에 한 줄로 합친다. 따로 보내지 않는다 | "새 단원 1곳이 열렸어요" |
| 주간 돌아보기 | 일요일, 그날 공부 알림 대신 | "이번 주 근거 9장을 익혔어요" |

**지키는 선**

- **하루 한 통이 최대.** 위 종류는 모두 한 통으로 합친다. 밤 10시~아침 8시에는 보내지 않는다.
- **기본 꺼짐.** 처음 방문에 묻지 않는다. **첫 판을 마친 뒤** 한 번 묻는다(잠금 화면 미리 보기를 보여 주고). 거절하면 7일 동안 다시 묻지 않는다.
- **잠금 화면에 내용 숨기기 기본 켬.** 알림에 정치 주제가 적히면 옆 사람이 본다. 켜 두면 "잼통이가 기다려요"만 적는다.
- 글은 정해 둔 틀뿐이다. 사람 이름·소문 문장·정치인 이름을 싣지 않는다.
- 연속일 압박 문구("끊겨요!", "실망이에요")를 쓰지 않는다.
- 아이폰은 홈 화면에 추가해야 받는다(`pushSupport()`의 `ios-home`). 설정 화면에 그대로 적는다.

**구조 — 정원과 다른 점**

- 정원 거대 잡초 알림은 "누가 켰는지의 장부를 두지 않는" FCM 주제 하나다. 모두에게 같은 글이 가니 가능했다.
- 공부 알림은 **목표를 채운 사람에게는 보내지 않아야** 하고 글도 사람마다 다르다. 그래서 장부가 필요하다.
  - `studyPush/{uid}` 문서: `{ token, hour, neutral, doneDay, tz: "Asia/Seoul" }`. 본인만 쓰고, 읽기는 서버(Admin SDK)만. 공개 필드 없음.
  - 판을 마칠 때 클라이언트가 `doneDay`를 오늘로 쓴다.
  - **보내는 쪽**: 매시 정각에 `/api/study/push/tick`(비밀 헤더로만 부를 수 있는 라우트)을 부른다. 그 시각을 고른 사람 가운데 `doneDay !== 오늘`인 사람에게만 보낸다. 부르는 쪽은 Cloud Scheduler(App Hosting 밖) — 설정을 `docs/deploy.md`에 더한다.
  - 글에 넣을 "다시 볼 카드 수"는 `studies/{uid}`에서 서버가 센다. 서버 밖으로 나가는 것은 정해 둔 틀의 숫자뿐이다.
  - 실패한 토큰(만료·해지)은 지운다. 알림을 끄면 문서를 지운다.
- 규칙 검사 `scripts/check-study-push-rules.ts`(`pnpm check:study-push-rules`) — 남의 문서를 읽거나 쓸 수 없는지, 클라이언트가 `token`·`hour`·`neutral`·`doneDay` 밖의 필드를 쓸 수 없는지.
- 서비스 워커는 정원과 같은 `push-sw.js`를 쓴다. 알림을 누르면 `/study`로 연다(데이터의 `link`).

### 8.6 피드백의 손맛

- 맞히면: 초록 막대가 차오르고, 잼통이가 뛰고, 짧은 소리와 진동(`gardenFeedback("reward")` 재사용).
- 틀리면: 붉은색으로 혼내지 않는다. 호박색 시트가 올라오고 잼통이가 "같이 볼까요?" — 풀이가 주인공이다.
- 연달아 맞히면 막대에 작은 불꽃. 점수로 바꾸지 않는다.
- 모든 동작은 `prefers-reduced-motion`을 지킨다. 접근성: 끌어 놓기 문항은 탭 두 번으로도 풀린다.

## 9. 디자인 에셋 — Codex CLI로 GPT에게 만들게

그림·애니메이션은 Codex CLI의 내장 이미지 생성(GPT)으로 만든다. `scripts/cartoon-gen.ts`의 길을 그대로 따른다.

### 9.1 원칙 (cartoon-gen과 같다)

- `codex exec --skip-git-repo-check -s workspace-write -C <작업폴더> "<프롬프트>" -i <참조 이미지>`, stdin은 닫는다. `codex login status`가 필요하다.
- 잼통이 시트(`assets/cartoons/jamtongi-sheet.png`)를 참조로 붙여 캐릭터를 맞춘다.
- **그림에 글자·숫자·로고를 넣지 않는다.** 글은 화면이 콘텐츠에서 얹는다.
- 실존 인물·정치인을 그리지 않는다. 종교 상징을 그리지 않는다. 듀오링고 등 특정 앱의 캐릭터·화풍을 따라 하지 않는다.
- 배경은 마젠타 단색으로 받아 투명하게 뺀다(`room-iso-gen.ts`의 방식). `cwebp`로 webp.
- 프롬프트와 날짜를 `public/images/study/prompts.json`에 남긴다. 만든 그림은 사람이 훑어보고, 맞지 않으면 지우고 다시 돌린다.

### 9.3 애니메이션을 만드는 방법

GPT 이미지 생성은 정지 그림을 낸다. 그래서 **움직임은 둘로 나눈다.**

1. **GPT가 그리는 것 — 키 포즈 프레임.** 같은 캐릭터의 포즈 3~4장을 한 장의 가로 시트로 요청한다(칸 크기·바닥선을 안내 이미지로 붙인다 — `room-iso-gen.ts`의 기하 안내와 같은 방법). 스크립트가 잘라 프레임으로 저장한다.
2. **코드가 하는 것 — 사이를 잇는 움직임.** 이미 의존성에 있는 `motion`으로 프레임 교체 + 눌림·늘어남·튀기·흔들기를 준다. 막대 차오름·카드 펼침·불꽃도 `motion`과 CSS로.

- Lottie·영상 파일은 쓰지 않는다(새 의존성, 용량). 필요해지면 그때 따로 판단한다.
- Codex에게 **코드 쪽 애니메이션 초안**(예: 판 끝 축하 연출의 `motion` 컴포넌트)도 맡길 수 있다. 그때는 `codex:codex-rescue` 길로 맡기고 결과를 리뷰해 합친다.

### 9.4 스크립트

```

pnpm study:art-gen mascot-cheer    하나만(있어도 다시)
pnpm study:art-gen --list          그릴 목록만
STUDY_ART_JOBS=3 pnpm study:art-gen
```

- 목록은 `src/features/study/art.ts`(id, 묶음, 프롬프트 조각, 크기, 프레임 수). 다 그린 것은 `src/features/study/artDone.json`에 적고, 화면은 목록에 없는 그림 대신 이모지로 그린다(그림이 늦어도 기능이 막히지 않게).

## 10. 문항 은행 — 만들고 지키는 법

### 10.1 저장 위치와 스키마

```
src/content/study/
  schema.ts          문항 유형별 zod 스키마 (oxItemSchema를 옮겨 확장)
  achievements.ts    업적 slug → 문항
  policies.ts        정책 slug → 문항 (소문에 답하기 포함)
  words.ts           언행 slug → 문항
  cartels.ts         카르텔 slug → 문항
  dialogs.ts         대화 답장 문항
  index.ts           STUDY_UNITS (길·단원·단계별 문항 id)
```

- `src/content/quizzes/ox.ts`는 `study/achievements.ts`로 옮기고, 정원의 잡초 퀴즈는 거기서 읽는다(문항 id 유지 — §7의 양방향 연결).
- 문항 id는 `<단원>/<문항>` 꼴로 **영구**다. 문장을 크게 고치면 새 id를 쓰고 옛 id는 `retired`로 둔다(사용자의 상자 기록이 엉뚱한 문항에 붙지 않게).
- 생성 가능한 것(사실·주장 가리기, 출처 고르기, 순서 맞추기)은 콘텐츠에서 **빌드 시 만든다**(`src/features/study/build.ts`, memorial/build.ts처럼). 손으로 쓸 것은 O/X·빈칸·반론·대화 답장뿐이다.

### 10.2 초안은 GPT, 확정은 대조

`ox.ts` 때와 같다. Codex(GPT)에게 **claim·반론·쉬운 설명만** 주고 초안을 쓰게 한 뒤, 문항마다 근거 claim과 대조해 고친다.
이 저장소의 에이전트(구독제)가 대조를 맡는다 — `scripts/`에서 모델 API를 부르지 않는다(AGENTS.md).

### 10.3 기계가 보는 것 — `pnpm validate`에 더한다

1. 모든 `claimIds`가 실재한다(정책·언행 앵커 포함).
2. 정답의 근거 claim 가운데 `verified: false`가 없다.
3. `CLAIM` 근거 문항의 문장에 `assertedBy`가 들어 있다.
4. `validUntil`이 지난 claim을 쓰는 문항이 없다(있으면 빌드에서 빠지고 경고).
5. 소문에 답하기 문항의 소문은 실제 `rumors` 항목이고 대응 claim이 있다.
6. 대화 답장의 "필수 카드"가 하나 이상, 보기 중 정답 아닌 카드는 다른 단원 것이다.
7. 단원마다 다섯 단계에 문항이 최소 수(알기 3, 이해 2, 출처 2, 반론 1, 말하기 1) 있다. 모자라면 그 단계는 잠긴 채 "준비 중".
8. 문항 id 중복 없음, `retired` id를 다시 쓰지 않음.

테스트는 `src/features/study/*.test.ts`에 두고 `garden:test`처럼 `study:test`로 묶어 `pnpm check`에 넣는다.

### 10.4 사람(에이전트)이 읽어서 보는 것

- 한 문항에 답이 둘로 읽히지 않는가.
- 반론 문항의 보기가 비판을 희화화하지 않는가.
- 판 끝 정답률이 유난히 낮은 문항(주간 집계) — 문항이 모호하다는 신호. 운영자 큐로 보낸다.

## 11. 저장과 규칙

- **localStorage 먼저, 계정이 있으면 Firestore**에 — 정원 store와 같은 방식(`src/features/garden/store.ts`).
- Firestore: `studies/{uid}` 문서 하나.

```ts
interface StudyData {
  v: 1;
  goal: 1 | 2 | 3;                 // 하루 판 수
  days: Record<string, number>;    // KST 날짜 → 그날 마친 판 수 (최근 400일)
  rests: { week: string; left: number };
  boxes: Record<string, [box: 1|2|3|4|5, due: string]>; // 문항 id → 상자, 다음 날짜
  steps: Record<string, number>;   // 단원 → 마친 단계(0~5)
  wallet: string[];                // 앵커
  badges: string[];
  rewardDay: string;               // 정원 보상 하루 상한 확인용
}
```

- 문항 1,000개여도 수십 KB — 문서 하나로 충분하다.
- `firestore.rules`: 본인만 읽고 쓴다. 공개 필드 없음(경쟁 없음의 기술적 보장 — 남의 기록을 읽을 길 자체가 없다).
  모양 검사(키 수 상한, 상자 1~5, 날짜 형식)를 넣고 `scripts/check-study-rules.ts`(`pnpm check:study-rules`)로 확인한다.
- 정원 보상(잼·씨앗)은 정원 문서 쪽에서 `rewardDay`로 하루 한 번만 받게 막는다.
- 분석 이벤트: `study_start`, `study_finish`(문항 수·정답 수), `study_item`(문항 id·정답 여부). 사람이 쓴 글·복사한 답장 내용은 보내지 않는다.

- 문항 정답률로 모호한 문항 고치기, 새 업적·정책이 들어오면 문항도 함께(정책 추가 순서에 "문항" 단계를 더하는 것을 검토).
- 지표: 7일 재방문율, 하루 목표 달성률, 근거노트 열람·복사 수(보상 없이 관찰만), 단원 열매 수.

## 13. 위험과 열린 질문

| 위험 | 대응 |
|---|---|
| 문항이 사실을 비틀어 "위키가 그렇게 말했다"로 퍼진다 | claim 대조·`validate`·X 문항 격리. 문항은 원본보다 강하게 말하지 않는다 |
| 한쪽만 가르치는 홍보물로 보인다 | 반론 단계가 필수 단계다. 반론 단계를 건너뛰면 단원이 열매가 되지 않는다 |
| 공부가 잼 채굴로 변한다 | 하루 보상 상한, 목표 초과분 보상 없음 |
| 연속일이 부담이 된다 | 쉼표 기본 제공, 끊김을 꾸짖지 않음, 알림은 기본 꺼짐(켜면 하루 한 번) |
| GPT 그림에 글자·실존 인물이 섞인다 | 프롬프트 금지 조항 + 사람 검수 + 그림 없을 때 이모지 대체 |

| 위키를 하단 탭에서 빼면 위키·AI 질문 이용이 준다 | 업적 탭 소속 + 상단 메뉴 + 교실의 「잼통이에게 묻기」. 교체 전후 2주 `/wiki` 방문 수를 비교하고, 크게 줄면 업적 탭 이름을 「업적·위키」로 바꾼다 |
