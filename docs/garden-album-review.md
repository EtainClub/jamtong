# 사진첩 개선 — 검토

> 상태: **구현 (2026-11-22)** — 아래 "구현" 절. 정한 것: 자유글 한 줄 허용, 언행·정책은 조건 없이, 퍼가기 잼 20·하루 100(댓글에는 잼 없음), 댓글 받기는 방명록 설정을 따른다.
> 계기: "올리는 내용이 모두 같아 사진첩을 쓸 이유가 적다. 싸이월드처럼 댓글을 달고 싶은데, 그러려면 사용자 고유의 내용이 있어야 한다. 그렇다고 사진을 마음대로 올리게 하는 것은 앱 정책상 좋지 않다. 업적 말고 언행과 다른 자료도 올릴 수 있게."

## 0. 결론

**사진을 올리는 대신 "골라서 담는다". 고유함은 사진 파일이 아니라 사용자의 선택·기록·순간에서 나온다.**

1. **무엇을 — 담을 것을 넓힌다.** 업적 카드 한 장에서 시작해 다음을 담는다.
   - 업적의 한 장면(카툰 한 칸, 숫자 하나, 반론 하나)
   - 언행의 한 토막
   - 정책 팩트 한 줄("도는 주장 → 확인한 사실")
   - 책의 한 장
   - **내 정원의 순간**: 황금 화분, 거대 잡초 처치, 기념품 퀴즈, 방 꾸민 모습 같은 기록. 앱이 기록을 바탕으로 그린다.
2. **어떻게 — 내 것을 얹는다.** 사진마다 "왜 담았나"를 단다. 정해진 문구와 스티커로 고르고, 폴더·대표 사진·올린 날짜를 둔다.
   사람이 쓴 글은 사실 칸과 떨어진 말풍선에만 둔다.
3. **누가 — 댓글과 퍼가기.** 방명록의 형식과 안전장치를 그대로 쓴다.
   - 형식: 정해진 문구 + 60자 한 줄 + 스티커
   - 안전장치: 링크·연락처·욕 거르기, 신고, 주인 가리기, 차단
   - 싸이월드의 "퍼가기"(스크랩)를 더한다. 자료가 사진 파일이 아니라 id라서, 퍼가도 출처와 근거가 그대로 따라간다.

이렇게 하면 같은 업적을 올려도 **"누가, 어느 장면을, 왜, 언제"**가 사진마다 다르다. 댓글은 그 차이에 달린다.

## 1. 지금 상태

| 무엇 | 지금 |

| 담는 것 | 거둔 업적 품종만. 업적 하나에 카드 하나(`PhotoCard`) — 사진·요약·숫자 셋·반론·링크. 누가 올려도 같다 |
| 사용자 몫 | 고르기와 내리기뿐. 순서·설명·날짜·묶음이 없다 |
| 저장 | 공개 문서 `room.album` 문자열(`a:<slug>,…`, 24장, 규칙이 정규식으로 본다) |
| 원칙 | "사진과 글은 모두 콘텐츠에서 온다 — 사람이 지은 글이 들어갈 자리가 없다"(`AlbumView.tsx`) |

## 2. 왜 같은 카드가 문제인가

싸이월드 사진첩을 보러 간 이유는 그 사진이 **그 사람의 것**이어서였다. 지금 카드는 업적 페이지의 축약판이다.

- 손님 입장에서는 업적 페이지를 보는 것과 같아, 남의 사진첩에 갈 이유가 없다.
- 주인이 고를 것이 "올린다/안 올린다"뿐이라 표현할 것이 없다.
- 그래서 댓글이 달릴 거리가 없다. "좋은 업적이네요"는 주인이 아니라 업적에 하는 말이다.

## 3. 지키는 선 — 사진 파일을 받지 않는 이유

이 선은 그대로 두고, 그 안에서 고유함을 만든다.

1. **사진 파일은 받지 않는다.**
   - 검수할 사람이 없다. 초상권·저작권 문제와 성적·폭력 이미지 신고를 감당할 체계도 없다.
   - 사진에 그린 글자는 걸러낼 수 없다.
   - 정치 사이트에서 합성 사진 한 장이 퍼지면 사이트 전체의 신뢰가 무너진다.
2. **사실 칸에는 콘텐츠만.** 숫자·주장·근거는 콘텐츠의 앵커에서 온다.
   `CLAIM`은 누구의 주장인지, `verified: false`는 "확인 전"이라고 표시한다. 지금 `PhotoCard`의 규칙과 같다.
3. **사람의 글은 사람의 글로 보이게.** 말풍선에 "○○의 한 줄"이라고 붙인다. 사실 칸과 모양·자리를 다르게 하고, 링크로 만들지 않는다.
4. **사용자 글은 자료가 아니다.** 사진첩 글과 댓글은 위키·factbase의 소스가 아니다(AGENTS.md의 Firestore 사용자 데이터와 같다).

## 4. 무엇을 담나 — 일곱 가지

모두 **id(앵커)로 담는다.** 위키가 쓰는 앵커 형식을 그대로 쓰니, 근거로 가는 길이 이미 있다.

| 종류 | 앵커 | 담는 곳 | 담는 조건 | 카드에 나오는 것 |
|---|---|---|---|---|
| 업적 | `<slug>` | 사진첩 | 거둔 업적 품종(지금과 같다) | 지금의 사진 카드 |
| 업적의 한 장면 | `<slug>#<claimId>` 또는 카툰 칸 id | 사진첩, 카툰 보기 | 거둔 업적 | 그 칸의 그림·말풍선이나 숫자 하나, 근거 |
| 반론 | `<slug>` + 반론 id | 사진 카드 | 거둔 업적 | 물음과 답, 근거. "반론도 같이 봐요"용 |
| 언행 토막 | `words:<slug>#<pointId>` | **언행 페이지의 "사진첩에 담기"** | 없음(읽은 자리에서 담는다) | 토막 제목, 쉬운 말, **원문 인용**, 날짜·채널 |
| 정책 팩트 | `policy:<slug>#<claimId>` | **정책 페이지의 "사진첩에 담기"** | 없음 | 도는 주장(있으면) → 확인한 사실, 주장한 사람, 확인 여부 |
| 책 한 장 | `/bk/<책>/<장>` | 독서대 | 그 책을 가졌다 | 장 제목·한 줄, 완독 도장이 있으면 도장 |
| **내 정원의 순간** | `m:<종류>:<id>` | 일이 일어난 자리(보상 창 등) | 그 기록이 내 장부에 있다 | 앱이 그린 기념 사진. 아래 4.1 |

정해진 수: 언행 61편 중 쉽게 보기 토막이 있는 것 51편, 정책 팩트 약 200건(통통 제외 195건). 업적 28건과 카툰 155칸.

**정책 팩트가 가장 쓸모 있다.** 목표 독자는 "지인에게 근거를 보내는 지지자"다.
"이 소문 봤어? 확인해 보니 이래"를 사진 한 장으로 담고, 그 사진의 링크를 보낸다. 사진첩이 그대로 근거 보관함이 된다.

### 4.1 내 정원의 순간 — 앱이 찍어 주는 사진

사용자가 직접 찍지 않아도, 앱은 그 사람에게만 있는 순간을 안다. 그때 "📷 사진첩에 담기"를 띄운다.

| 순간 | 그림 | 근거(누가 확인하나) |
|---|---|---|
| 황금·무지개 열매 수확 | 그 품종 열매 + 날짜 | 내 장부(주인만 쓴다) |
| 거대 잡초 처치 | 잡초 모습, 별 수, 함께한 사람 수, 내 역할 | 공유 문서 `plazaRaids/<물결>/fighters/<uid>` — 규칙으로 확인할 수 있다 |
| 기념품 획득 | 기념품 그림 + 맞힌 퀴즈 물음 | 내 장부 |
| 새 품종 도감 | 품종 그림, 몇 번째 품종인지 | 내 장부 |
| 방 꾸민 모습 | 그날의 방(`RoomSvg`로 그린다) — 방 배치를 사진에 굳혀 둔다 | 공개 방 문서 |
| 완독 도장 | 책 색 표지 + 도장 | 내 장부 |
| 1촌 맺은 날 | 두 꼬마 + 1촌 이름표 | `ilchon/{uid}` 문서 |

- 그림은 이미 있는 부품으로 그린다(정원 픽셀 아트, `RoomSvg`, og 렌더러). 새 AI 그림은 필요 없다.
- 사진에는 **기록에 있는 것만** 쓴다(날짜·수·이름). 지어낸 글이 들어갈 자리가 없다.
- 자기 장부의 기록은 주인이 고칠 수 있으니 "자기 기록"으로만 보인다. 남과 견주는 수(순위)는 넣지 않는다.

## 5. 내 것을 얹기 — 사진 한 장의 모양

```
┌──────────────────────────────┐
│ [그림 / 카툰 칸 / 기념 사진]     │  ← 콘텐츠·앱이 그린다
│ 정책 팩트 · 확인함              │
│ 도는 주장: "…"                  │
│ 확인한 사실: "…" ^근거          │  ← 사실 칸(앵커)
├──────────────────────────────┤
│ 💬 ○○의 한 줄  🌱               │  ← 사람의 칸(모양을 달리)
│ "주변에 알려 주고 싶어요"         │
│  + 엄마가 물어봐서 찾아봤어요     │  ← (2단계) 60자, 방명록과 같은 검사
│ 2026.11.22 · 📁 알려 주고 싶은 것 │
├──────────────────────────────┤
│ 댓글 3 · 퍼감 2 · [퍼가기]        │
└──────────────────────────────┘
```

- **왜 담았나(문구)**: 고르기만 한다. 예:
  - "처음 알았어요"
  - "주변에 알려 주고 싶어요"
  - "반론도 같이 봐야 해요"
  - "더 지켜볼게요"
  - "이 숫자 기억할래요"
  - "직접 확인했어요"
  - "궁금한 게 남았어요"

  사실을 평가하는 문구("거짓이에요"·"최고예요")는 두지 않는다.
- **한 줄(선택, 2단계)**: 60자. 방명록과 같은 `lineProblem` 검사를 하고, 신고·가리기를 둔다.
  공개 방 문서에는 싣지 않고 별도 문서에 둔다. "공개 문서에는 글을 싣지 않는다"는 지금 원칙을 지킨다.
- **폴더**: 이름은 정해진 목록에서 셋까지 고른다. 예:
  - 알려 주고 싶은 것
  - 공부 중
  - 내 정원 기록
  - 책갈피
  - 소문 확인
- **대표 사진**: 하나. 방 액자와 1촌 새 소식에 쓴다.
- **날짜**: 올린 날을 자동으로 붙인다. 같은 업적이라도 "언제 담았나"가 다르다.

## 6. 댓글과 퍼가기

### 6.1 댓글 — 방명록을 그대로

| 무엇 | 방명록에서 가져오는 것 | 사진첩에서 다른 것 |
|---|---|---|
| 형식 | 정해진 문구 + 60자 한 줄 + 스티커(`Line {p,x,k}`) | 사진첩용 문구(아래) |
| 거르기 | `lineProblem`: 링크·연락처·욕 | 같다 |
| 수 | 한 사람이 한 방에 하루 한 번 | **한 사진에 하루 한 번** |
| 받기 | 모두 / 1촌만 / 받지 않음 | 방명록 설정을 따르고, 사진마다 끌 수 있다 |
| 지키기 | 주인 지우기, 주인 가리기, 신고(feedback), 차단, 운영자 가리기 | 같다 |
| 보이기 | 최근 30개 | 사진마다 최근 20개 |

사진첩용 댓글 문구 예:
- "저도 몰랐어요"
- "근거 봤어요"
- "반론도 봤어요"
- "퍼 갈게요"
- "같이 지켜봐요"
- "좋은 장면이에요"
- "덕분에 알았어요"
- "1촌 해요"

**"근거 봤어요"는 실제로 근거를 열었을 때만 고를 수 있게 한다**(화면에서 연 표식). 근거 열람률은 이 사이트의 핵심 지표다.

### 6.2 퍼가기 — 싸이월드의 확산 고리

- 남의 사진을 내 사진첩에 담는다. "○○의 사진첩에서" 출처가 붙는다. 사진이 id라서 근거와 표시가 그대로 따라온다.
- 원래 사진에 "퍼감 n"이 쌓인다. 주인은 1촌 새 소식으로 "○○가 퍼 갔어요"를 받는다.
- 보상: 내 사진이 퍼가지면 잼 20, 하루 100잼까지.
  댓글에는 잼을 주지 않는다. 주면 "다녀갑니다" 도배가 생긴다.
- 퍼간 사진의 "왜 담았나"는 내가 다시 고른다. 남의 한 줄은 따라오지 않는다.

## 7. 밖으로 — 사진 한 장의 링크

- `/g/<공개id>/p/<사진id>`: 크롤러에는 "○○의 사진첩에서" 카드를 보이고, 사람은 그 사진과 근거로 간다. 책의 장 카드(`/bk/…?g=`)와 같은 방식이다.
- 카드에는 언제나 앵커의 사실과 출처 표시가 있다. 사람의 한 줄은 카드 그림에 넣지 않는다. 미리보기가 퍼질 때 사용자 글이 사실처럼 보이지 않게 하기 위해서다.
- 이것이 "지지자가 지인에게 근거를 보내는" 쓰임과 바로 이어진다. 언행·정책 페이지의 "사진첩에 담기"는 사이트에서 정원으로 오는 길이 된다.

## 8. 자료 구조와 규칙

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 사진 | 공개 문서 `room.album` 문자열 | `gardens/{gid}/photos/{pid}` 문서 하나에 한 장 |
| 필드 | slug | `a`(앵커), `t`(종류), `p`(문구 번호), `k`(스티커), `f`(폴더 번호), `at`(올린 때), `from`(퍼온 방·사진, 있으면), `x`(한 줄, 2단계) |
| 댓글 | — | `photos/{pid}/comments/{uid}_{날}` — 방명록 문서와 같은 모양 |
| 퍼감 수 | — | 원래 사진의 `n` 하나 늘리기(규칙: 1씩만, 퍼온 사진이 실제로 있을 때) |

- 규칙은 앵커의 **모양**을 본다. 종류마다 정규식을 둔다(`words:[a-z0-9-]+#[a-z0-9-]+` 등).
  앵커가 실제로 있는지는 화면에서 콘텐츠 목록으로 확인한다. 없어진 자료는 "더 이상 없는 자료" 카드로 그리고, 링크를 만들지 않는다.
- 거대 잡초 사진처럼 공유 문서로 확인할 수 있는 순간은 규칙에서 `exists()`로 확인한다. 장부에만 있는 순간은 자기 기록으로 둔다.
- 옮기기: 정원을 열 때 `room.album`의 업적을 사진 문서로 옮기고 문자열은 비운다. 장수 상한은 24장에서 60장으로 늘린다(폴더가 생기므로).
- 점검: 방명록처럼 에뮬레이터 규칙 테스트를 둔다(`check:*-rules`). 배포는 규칙 먼저.

## 9. 순서

| 단계 | 내용 | 크기 | 댓글의 의미 |
|---|---|---|---|
| 1 | 담을 것 넓히기: 업적 장면, 언행 토막, 정책 팩트, 책 한 장. 사이트 페이지에 "사진첩에 담기" 단추. 문구·폴더·날짜·대표 사진. 저장 구조 옮기기 | 3–4일 | 생긴다(선택과 이유가 다르다) |
| 2 | 댓글(방명록 재사용), 퍼가기, 1촌 새 소식 | 2–3일 | 달린다 |
| 3 | 내 정원의 순간 사진(거대 잡초·황금 열매·기념품·방·완독·1촌) | 2–3일 | 축하 댓글이 붙는다 |
| 4 | 사진 링크 카드(`/g/…/p/…`), 사진의 한 줄(60자) | 1–2일 | 밖에서 들어온다 |

## 10. 정해야 할 것

1. **사진의 한 줄(자유글)을 둘까?** 권고: 1단계는 문구만 두고, 2단계에 방명록 수준(60자, 거르기·신고)으로 연다.
   정치 자료 옆에 붙는 글이라 방명록보다 위험하다. 실제 신고 수를 보고 정한다.
2. **언행·정책을 조건 없이 담게 할까?** 권고: 조건 없이, 단 그 자료 페이지에서만 담는다(읽은 자리에서 담기).
   업적은 지금처럼 "거둔 것만"으로 두어 정원의 보상 의미를 지킨다.
3. **퍼가기 보상**: 잼 20, 하루 100이 적당한가?
4. **댓글 받기 기본값**: 방명록 설정을 따르게 할까(권고), 1촌만으로 시작할까?
